--------------------------------------------------------------------------------
1. DATA ACQUISITION
--------------------------------------------------------------------------------

Continuous single-channel electroencephalographic (EEG) recordings were
obtained from 102 mice enrolled in the UNIQURE preclinical epilepsy
study. Each recording was acquired as a single EEG channel digitised at
a sampling frequency of 500 Hz and stored in European Data Format (EDF).
One EDF file was generated per subject (e.g., m1.edf). Recording
durations varied across subjects, ranging from several hours to multiple
days of uninterrupted monitoring.

Seizure events were annotated independently in Excel spreadsheets (.xlsx),
with one annotation file per subject (e.g., m1_xlsx.xlsx). Each row
specified the onset ('start_time') and offset ('end_time') of a single
electrographic seizure in absolute datetime format (DD/MM/YYYY
HH:MM:SS.fff). For computational use, all annotation timestamps were
converted to elapsed seconds relative to the EDF recording start time
extracted from the file header.

--------------------------------------------------------------------------------
2. DATA PARTITIONING
--------------------------------------------------------------------------------

To ensure unbiased evaluation, the 102 subjects were assigned to three
mutually exclusive partitions at the animal level prior to any model
development:

    Partition       Subjects    Purpose
    --------------- ----------- -------------------------------------------
    Training        72          Model fitting and hyperparameter tuning
    Validation      ~10         Early stopping, threshold optimisation
    Test            ~10         Final held-out evaluation (reserved)

Subject-level partitioning guarantees that no EEG data from the same
animal appears in more than one partition. This design prevents inflated
performance estimates that arise when temporally correlated segments from
a single recording are distributed across training and evaluation sets
(Gemein et al., 2020) [VERIFY EXACT QUOTE BEFORE SUBMISSION].

An automated leakage check was executed at the time of partition
generation to confirm that no subject identifier appeared in more than
one split. This check is enforced programmatically each time the
data manifest is regenerated.

Reference:
    Gemein, L. A. W., Schirrmeister, R. T., Chrabąszcz, P., Wilson, D.,
        Boedecker, J., Schulze-Bonhage, A., Hutter, F., & Ball, T. (2020).
        Machine-Learning-Based Diagnostics of EEG Pathology. NeuroImage,
        220, 117021. https://doi.org/10.1016/j.neuroimage.2020.117021

--------------------------------------------------------------------------------
3. PREPROCESSING
--------------------------------------------------------------------------------

Prior to segmentation, each continuous EEG recording was subjected to
a three-stage preprocessing pipeline applied sequentially:

(i) Powerline interference removal. A second-order zero-phase IIR notch
    filter centred at 50 Hz (quality factor Q = 30) was applied using
    forward-backward filtering (scipy.signal.filtfilt) to suppress mains
    interference while preserving the amplitude and phase of adjacent
    frequency components.

(ii) Baseline correction. The arithmetic mean of each processing block
     was subtracted to eliminate any DC offset introduced by the recording
     hardware or electrode drift.

(iii) Robust amplitude normalisation. Each block was normalised using
      the robust z-score:

          z = (x - median(x)) / (1.4826 * MAD(x))

      where MAD denotes the median absolute deviation. The scaling
      constant 1.4826 ensures consistency with the standard deviation
      under a Gaussian distribution (Rousseeuw & Croux, 1993). The
      median and MAD were chosen over the mean and standard deviation
      because of their resistance to the large-amplitude transients
      characteristic of rodent EEG, including grooming artefacts and
      movement-related spikes.

To manage memory constraints on the high-performance computing cluster,
the preprocessing pipeline was applied in contiguous blocks of 40
segments rather than loading entire recordings into memory.

Reference:
    Rousseeuw, P. J. & Croux, C. (1993). Alternatives to the Median
        Absolute Deviation. Journal of the American Statistical
        Association, 88(424), 1273-1283.

--------------------------------------------------------------------------------
4. SEGMENTATION
--------------------------------------------------------------------------------

Each preprocessed recording was divided into fixed-length segments using
a sliding window approach with the following parameters:

    Parameter           Value       Description
    ------------------- ----------- -----------------------------------------
    Window length       2,500       5 seconds at 500 Hz
    Step size           1,250       2.5 seconds (50% overlap)
    Segment dimensions  (1, 2500)   Single channel, 2,500 time points

A 50% overlap between consecutive windows was employed to augment the
effective training set size and to preserve temporal continuity across
adjacent segments. Each segment was stored as an individual NumPy array
file (.npy) in 32-bit floating-point format, occupying approximately
10 KB per segment.

The naming convention for output files follows the pattern:
    {subject_id}_{ictal|nonictal}_{index:05d}.npy

where the index is a sequential one-based counter per class per subject
(e.g., m1_ictal_00001.npy, m1_nonictal_00003.npy). This counter
reflects the temporal order of segments within the recording but does
not encode the absolute grid position.

--------------------------------------------------------------------------------
5. SEGMENT LABELLING
--------------------------------------------------------------------------------

Binary labels were assigned to each segment based on temporal overlap
with the annotated seizure intervals. A segment spanning the time
interval [t_start, t_end) was labelled as ictal (y = 1) if it satisfied
the overlap condition:

    t_start < seizure_end  AND  t_end > seizure_start

for at least one annotated seizure interval. Under this criterion, any
degree of temporal overlap -- including a single sample -- classifies
the segment as ictal. All remaining segments were labelled as non-ictal
(y = 0).

This any-overlap labelling strategy was adopted to maximise sensitivity
to seizure boundaries, ensuring that onset and offset segments are
included in the ictal class even when only partially overlapping with
the annotated event.

6. MODEL ARCHITECTURE
--------------------------------------------------------------------------------

Four models are evaluated in an ablation study to isolate the
contributions of multi-scale temporal processing and temporal attention:

    Model   Architecture                        Ablation role
    ------- ----------------------------------- ---------------------------
    M1      TCN                                 Baseline
    M2      TCN + Temporal Attention            + attention over M1
    M3      Multi-Scale TCN                     + multi-scale over M1
    M4      Multi-Scale TCN + Temporal Attention + both over M1

All four models share the same CausalConvBlock as their fundamental
building unit.

6.1 CausalConvBlock (residual block)

    Each residual block comprises two dilated causal one-dimensional
    convolutional layers operating at the same dilation factor
    (d = 2^L, where L denotes the layer index), following the temporal
    convolutional network (TCN) architecture proposed by Bai et al.
    (2018). The use of two convolutional layers at each dilation level
    enables multiple non-linear transformations to be learned before
    progressing to larger receptive fields, thereby enhancing
    representational capacity.

    Each convolution is followed by layer normalisation applied across
    the feature-map channel dimension, Gaussian Error Linear Unit (GELU)
    activation, and spatial dropout (Dropout1d). Layer normalisation is
    employed in place of batch normalisation to mitigate the effects of
    inter-subject variability in EEG amplitude and the instability of
    batch statistics under relatively small batch sizes (16-64). Spatial
    dropout (nn.Dropout1d) is used instead of element-wise dropout
    (nn.Dropout) to provide structured regularisation appropriate for
    convolutional feature maps. For a tensor of shape
    (batch, num_filters, time), spatial dropout zeros entire
    feature-map channels across the full time dimension, whereas
    element-wise dropout zeros individual (feature-map, time-step)
    cells independently. Because adjacent time steps within a single
    convolutional feature map are highly correlated (they share
    overlapping receptive fields through the same filter), element-
    wise dropout on a single cell is trivially recovered from its
    temporal neighbours and produces weak regularisation. Spatial
    dropout removes an entire feature map for a given forward pass,
    forcing representational redundancy across the num_filters
    channels (Tompson et al., 2015). Note that "channel" in this
    context refers to a learned convolutional feature map, NOT to an
    EEG recording electrode: the input EEG is single-channel (one
    electrode per recording), so the input tensor has shape
    (batch, 1, time); the num_filters dimension is introduced after
    the first convolution. GELU activation is adopted to facilitate
    smoother gradient propagation and improved modelling of
    continuous biosignal dynamics. A 1x1 pointwise convolution is used to form the residual
    skip connection when required for dimensionality matching. Causal
    padding with right-side trimming is applied throughout to preserve
    temporal causality and prevent leakage of future information during
    sequence modelling.

    Architecture diagram (single CausalConvBlock):

    Input x (F_in channels, T time steps)
    |
    |--[ Residual path ]--------------------------------------------.
    |                                                               |
    +--[ Conv1d(F_in, F_out, k, dilation=d, causal padding) ]      |
    |       |                                                       |
    |       +--[ Trim right (remove future samples) ]               |
    |       |                                                       |
    |       +--[ LayerNorm (channel dim) ]                          |
    |       |                                                       |
    |       +--[ GELU ]                                             |
    |       |                                                       |
    |       +--[ Dropout1d (spatial, feature-map-channel-wise) ]    |
    |                                                               |
    +--[ Conv1d(F_out, F_out, k, dilation=d, causal padding) ]     |
    |       |                                                       |
    |       +--[ Trim right ]                                       |
    |       |                                                       |
    |       +--[ LayerNorm ]                                        |
    |       |                                                       |
    |       +--[ GELU ]                                             |
    |       |                                                       |
    |       +--[ Dropout1d ]                                        |
    |                                                               |
    +--[ + ]<------[ 1x1 Conv (if F_in != F_out) ]<----------------'
    |           or identity (if F_in == F_out)
    |
    Output (F_out channels, T time steps)

    The receptive field of L stacked CausalConvBlocks with exponentially
    increasing dilation (d = 1, 2, 4, ..., 2^(L-1)) and two
    convolutions per block is:

        RF = 2 * (2^L - 1) * (k - 1) + 1

    where k is the kernel size. For example, with L = 6 layers and
    k = 7, the receptive field spans 757 samples (1.514 s at 500 Hz).

6.2 Shared output components

    While the four models differ in their temporal feature extraction
    strategy (single-branch vs multi-scale, uniform vs attention-based
    aggregation), they share a common downstream pathway from temporal
    aggregation through to the training objective. This standardised
    output design ensures that performance differences across the
    ablation study are attributable to the upstream architectural
    variation rather than to differences in the classification head,
    loss function, optimiser, or training procedure.

    (i) Temporal aggregation: global average pooling.

        After the convolutional backbone processes a 5-second EEG
        segment, the resulting temporal feature map H has shape
        (batch, F, T), where F denotes the number of convolutional
        filters and T denotes the number of output time steps. Because
        causal padding preserves the input length, T remains equal to
        the original 2,500 samples throughout the convolutional stack.

        This high-dimensional sequence must be reduced to a fixed-
        length vector before classification. In M1 (TCN) and M3
        (Multi-Scale TCN), this reduction is performed by global
        average pooling, which computes the arithmetic mean of the
        feature vectors across all T time steps:

            z = (1/T) * sum_{t=1}^{T} h_t        z in R^F

        This operation collapses the temporal dimension entirely,
        producing a single F-dimensional summary vector z that
        represents the average activation pattern over the full
        5-second segment. By treating every time step with equal
        weight, global average pooling assumes that seizure-
        discriminative information is distributed uniformly across
        the segment rather than concentrated at specific temporal
        locations.

        In M2 (TCN + Attention) and M4 (Multi-Scale TCN + Attention),
        global average pooling is replaced by a learned temporal
        attention mechanism (described in Section 6.4). Rather than
        assigning uniform weight 1/T to every time step, the
        attention module learns data-dependent weights alpha_t that
        allow the model to focus on the most seizure-informative
        portions of the segment. This replacement is the central
        architectural variable in the M1-vs-M2 and M3-vs-M4 ablation
        comparisons.

    (ii) Classification head: single linear layer.

         The aggregated feature vector z in R^F -- whether obtained
         from global average pooling (M1, M3) or from the attention-
         weighted context vector (M2, M4) -- is projected to a single
         scalar output by a fully connected linear layer:

             logit = w^T z + b

         where w in R^F is the learned weight vector and b in R is
         the bias term. This layer contains F + 1 trainable parameters
         and produces an unbounded real-valued output (the logit) that
         represents the model's unnormalised confidence that the input
         segment contains seizure activity.

         Critically, no activation function is applied after this
         layer during training. The raw logit is passed directly to
         the loss function, which internally applies the sigmoid
         transformation. This design avoids the numerical instability
         that arises from computing log(sigmoid(x)) separately, as
         discussed below.

         At inference time, the sigmoid function is applied explicitly
         to convert the logit to a probability estimate p in [0, 1]:

             p = sigma(logit) = 1 / (1 + exp(-logit))

         A segment is classified as ictal if p >= threshold, where
         the threshold is either the default value of 0.5 or the
         Youden-optimal threshold determined from the validation set.

    (iii) Training objective: binary cross-entropy with logits.

          The network is trained to minimise the binary cross-entropy
          (BCE) loss, computed using PyTorch's BCEWithLogitsLoss. This
          function fuses the sigmoid activation and the BCE computation
          into a single operation that exploits the log-sum-exp
          identity for numerical stability:

              L(logit, y) = -[ y * log(sigma(logit))
                            + (1 - y) * log(1 - sigma(logit)) ]

          where y in {0, 1} is the ground-truth binary label (1 for
          ictal, 0 for non-ictal) and sigma denotes the sigmoid
          function. When the logit is a large positive number and y=1,
          or a large negative number and y=0, the naive computation of
          log(sigma(.)) would suffer from floating-point underflow.
          The fused implementation avoids this by reformulating the
          expression using numerically stable primitives.

          The pos_weight parameter, which scales the loss contribution
          of positive (ictal) samples, is set to 1.0. Class imbalance
          is instead addressed entirely through offline stratified
          downsampling of the training corpus (Section 9). This
          separation of concerns ensures that the loss function treats
          each training sample with equal weight, preventing the
          gradient magnitude distortion that can arise when pos_weight
          is set to large values (e.g., 438 for the raw 1:438
          imbalance ratio). Such distortion would disproportionately
          amplify gradients from ictal samples, potentially causing
          optimiser instability and overconfident predictions on the
          minority class.

6.3 M1: TCN (baseline)

    L CausalConvBlocks are stacked sequentially with exponentially
    increasing dilation factors (d = 1, 2, 4, ..., 2^(L-1)). The
    output is globally average-pooled along the temporal axis and
    passed through a linear classification head producing a single
    logit for binary seizure detection.

    Input (1 x 2500)
    |
    +--[ CausalConvBlock, d=1   ]
    +--[ CausalConvBlock, d=2   ]
    +--[ CausalConvBlock, d=4   ]
    +--[ ...                    ]
    +--[ CausalConvBlock, d=2^(L-1) ]
    |
    +--[ Global Average Pool (T -> 1) ]
    |
    +--[ Linear(F, 1) ]
    |
    logit

    Tunable hyperparameters: num_layers (L), num_filters (F),
    kernel_size (k), dropout rate.

6.4 M2: TCN + Temporal Attention

    M2 replaces the global average pooling of M1 with a two-layer
    additive temporal attention mechanism that learns to assign
    non-uniform importance weights to individual time steps. The
    TCN backbone is identical to M1; the only architectural
    difference is the aggregation stage.

    6.4.1 Motivation

    Global average pooling treats every time step equally, which
    implicitly assumes that seizure-discriminative information is
    distributed uniformly across the 5-second segment. In practice,
    seizure onset or offset patterns may be concentrated in a
    fraction of the window, while the remainder contains background
    EEG that dilutes the discriminative signal. A learned attention
    mechanism allows the model to focus on the most informative
    temporal regions, potentially improving both classification
    accuracy and interpretability (the attention weights form a
    temporal saliency map over the raw EEG segment).

    6.4.2 Two-layer additive attention: step by step

    The TCN backbone produces a temporal feature sequence:

        H = [h_1, h_2, ..., h_T]       H in R^(T x F)

    where T = 2,500 (the segment length preserved by causal padding)
    and F = num_filters (the channel dimension from the final
    CausalConvBlock). Each h_t in R^F is a learned representation of
    the EEG signal at time step t.

    The attention mechanism processes H in four stages:

    Stage 1 -- Projection (Linear + tanh):

        e_t = tanh(W_a * h_t + b_a)        for each t = 1, ..., T

        W_a in R^(D_a x F) is a learnable weight matrix that projects
        each F-dimensional feature vector h_t into a D_a-dimensional
        attention space. b_a in R^(D_a) is a learnable bias. The
        hyperbolic tangent (tanh) activation squashes each element of
        the projected vector to the range [-1, +1], introducing the
        non-linearity that allows the scoring function to capture
        feature interactions that a purely linear projection cannot.

        D_a (attention_dim) is a tunable hyperparameter controlling
        the dimensionality of this intermediate representation. A
        larger D_a increases the expressiveness of the scoring function
        but adds parameters. In this study, D_a is selected from
        {32, 64, 128} by Optuna.

    Stage 2 -- Scoring (Linear, no bias):

        s_t = v^T * e_t                     for each t = 1, ..., T

        v in R^(D_a) is a learnable vector (implemented as
        nn.Linear(D_a, 1, bias=False)) that reduces each D_a-
        dimensional energy vector e_t to a single scalar score s_t.
        This score represents the unnormalised importance of time
        step t. The absence of bias ensures that the scoring function
        is centred: a zero-energy vector produces a zero score.

    Stage 3 -- Normalisation (Softmax):

        alpha_t = exp(s_t) / sum_{j=1}^{T} exp(s_j)

        The softmax function converts the T unnormalised scores into
        a proper probability distribution over time steps. The
        resulting attention weights alpha_t satisfy two properties:
        (a) alpha_t >= 0 for all t (non-negativity), and (b)
        sum_{t=1}^{T} alpha_t = 1 (normalisation). A time step with
        a high score receives a large weight; a time step with a low
        score receives a near-zero weight.

    Stage 4 -- Aggregation (Weighted sum):

        c = sum_{t=1}^{T} alpha_t * h_t        c in R^F

        The context vector c is a weighted average of the original
        feature vectors h_t, where the weights alpha_t are determined
        by the learned scoring function rather than fixed at 1/T.
        Unlike global average pooling, this allows the model to
        concentrate its representation on the temporal regions most
        relevant to seizure detection.

    After aggregation, dropout is applied to the context vector c
    (with rate attention_dropout, tunable in [0.0, 0.4]) to
    regularise the attention output and prevent the model from
    relying on a single dominant time step. The regularised context
    vector is then passed to the shared linear classification head
    (Section 6.2).

    6.4.3 Learnable parameters

    The attention module introduces three sets of learnable parameters:

        Component           Shape               Parameters
        ------------------- ------------------- --------------------
        W_a (projection)    (D_a x F)           D_a * F + D_a (bias)
        v   (scorer)        (D_a x 1)           D_a (no bias)
        Dropout             --                  0 (no learnable params)

        Total attention parameters: D_a * (F + 2)

    For D_a = 64 and F = 64: 64 * 66 = 4,224 parameters. This is
    a small fraction (~2-5%) of the total model parameters, meaning
    the attention mechanism adds minimal computational overhead while
    providing temporal selectivity and interpretability.

    6.4.4 Interpretability: attention as saliency

    The attention weights alpha_t provide an intrinsic interpretability
    mechanism. By inspecting alpha_t across the T = 2,500 time steps,
    one can visualise which temporal regions the model considers most
    relevant for its seizure/non-seizure decision. A method
    get_attention_weights(x) is provided that extracts these weights
    for any input segment, enabling:

      - Per-segment saliency maps overlaid on raw EEG waveforms
      - Class-averaged attention profiles (mean alpha_t for ictal vs
        non-ictal segments)
      - Differential attention analysis (ictal minus non-ictal mean
        attention, highlighting time steps where the model attends
        more to seizure segments)
      - Event-level attention profiles stratified by detection
        outcome (TP, FP, FN), reconstructed across overlapping
        windows via overlap-add and aligned at event onset
        (Section 7.6.13). This view distinguishes saliency for
        correct detections from the two failure modes, which the
        class-averaged view cannot.

    The first three visualisations are produced automatically
    during training (Figure 13 in the training scripts). The event-
    level outcome-stratified analysis is a separate post-training
    pass (event_attention_saliency.py) run on both val and test;
    see Section 7.6.13.

    6.4.5 Architecture diagram

    Input (1 x 2500)
    |
    +--[ TCN backbone: L CausalConvBlocks, d=1,2,...,2^(L-1) ]
    |
    |  H: (batch, F, T) -- temporal feature maps
    |
    +--[ Transpose -> (batch, T, F) ]
    |
    |  For each time step t:
    |
    +--[ Linear(F, D_a) ]----> W_a * h_t + b_a     (projection)
    |       |
    |       +--[ tanh ]------> e_t in R^(D_a)       (non-linear energy)
    |       |
    |       +--[ Linear(D_a, 1, no bias) ]--> s_t   (scalar score)
    |
    +--[ Softmax over T ]----> alpha_t               (attention weights)
    |                          alpha_t >= 0, sum = 1
    |
    +--[ Weighted sum: c = sum(alpha_t * h_t) ]      (context vector)
    |                          c in R^F
    |
    +--[ Dropout(attention_dropout) ]                (regularisation)
    |
    +--[ Linear(F, 1) ]                              (classification head)
    |
    logit

    6.4.6 Design choices and justification

    The two-layer additive formulation (project + tanh + score) was
    chosen over simpler alternatives for two reasons:

    (a) A single-layer linear scorer (s_t = w^T h_t) computes a
        fixed linear combination of feature channels. It cannot learn
        non-linear feature interactions (e.g., "attend to time steps
        where channel A is high AND channel B is low"). The
        intermediate tanh projection enables such interactions.

    (b) Multi-head self-attention (Transformer-style) computes
        pairwise interactions between all T^2 time step pairs. With
        T = 2,500, this would produce a 2,500 x 2,500 attention
        matrix per head, adding substantial memory and compute cost
        for a binary classification task where the output is a single
        scalar, not a sequence. The additive formulation computes
        T independent scores with O(T) complexity.

    This formulation is identical in M2 (over the single-branch TCN
    backbone) and M4 (over the multi-scale TCN backbone), ensuring
    that the M2-vs-M4 comparison isolates the backbone architecture
    rather than attention design differences.

    Additional tunable hyperparameters: attention_dim (D_a),
    attention_dropout. (Full search space in Section 7.3.)

    Ablation: M2 vs M1 isolates the contribution of learned temporal
    attention over uniform average pooling. If M2 outperforms M1,
    the temporal attention mechanism captures seizure-relevant
    temporal structure that uniform averaging fails to exploit.

6.5 M3: Multi-Scale TCN

    Three parallel branches process the input simultaneously, each
    operating at a different temporal resolution defined by its
    dilation schedule:

        Branch 1 (fine):         dilations [1,  2,   4]   -- spike morphology
        Branch 2 (intermediate): dilations [8,  16,  32]  -- rhythmic bursts
        Branch 3 (coarse):       dilations [32, 64, 128]  -- seizure evolution

    Each branch consists of three CausalConvBlocks arranged
    sequentially -- one block per dilation value. For example,
    Branch 1 contains: block at d=1, followed by block at d=2,
    followed by block at d=4. Since each CausalConvBlock internally
    comprises two dilated convolutional layers (as described in
    Section 6.1), each branch contains 3 blocks x 2 convolutions
    = 6 convolutional layers, and the full three-branch model
    contains 18 convolutional layers in parallel.

    Importantly, each branch is NOT a single residual block. The
    dilation list [1, 2, 4] specifies three separate blocks stacked
    in sequence within that branch, with each block operating at a
    progressively larger dilation factor. This stacking within each
    branch provides a branch-local receptive field given by:

        RF_branch = 1 + 2 * (k - 1) * sum(dilations)

    At the maximum tuned kernel size k=7:
        Branch 1:   RF =  85 samples =  170 ms at 500 Hz
        Branch 2:   RF = 673 samples = 1.35 s
        Branch 3:   RF = 2689 samples = 5.38 s (spans full 5-s segment)

    The dilation schedules are selected so the three branches jointly
    cover the physiological temporal scales of rodent EEG seizures:
    sub-second spike complexes, ~0.4-1.4 s rhythmic bursts, and
    full-segment ictal envelopes. The coarse branch's 5.38 s
    receptive field guarantees that each segment is classified with
    full temporal context available at fusion.

    All three branches use a geometric doubling progression
    (d_{i+1} = 2 * d_i). This follows the canonical TCN dilation
    pattern established by Bai et al. (2018), under which each
    added block approximately doubles the branch receptive field.
    The progression is deliberately regular across all three
    branches: the fine branch begins the series at d=1, and the
    intermediate and coarse branches continue the same doubling
    pattern starting from higher offsets (d=8 and d=32). This
    uniformity is adopted for architectural and reporting clarity
    rather than as a training-stability claim -- a single, regular
    doubling rule applied across branches is simpler to describe,
    reproduce, and compare against other TCN variants in the
    literature than ad-hoc per-branch schedules would be.

    Branch outputs are fused (concatenation with 1x1 projection, or
    element-wise average), globally average-pooled, and classified.

    Input (1 x 2500)
    |
    +----------------+------------------+------------------+
    |                |                  |                  |
    | Branch 1       | Branch 2         | Branch 3         |
    | Block d=1      | Block d=8        | Block d=32       |
    | Block d=2      | Block d=16       | Block d=64       |
    | Block d=4      | Block d=32       | Block d=128      |
    | (3 blocks,     | (3 blocks,       | (3 blocks,       |
    |  6 conv layers)|  6 conv layers)  |  6 conv layers)  |
    |                |                  |                  |
    +----------------+------------------+------------------+
    |
    +--[ Fusion: concat + 1x1 Conv  OR  element-wise average ]
    |
    +--[ Global Average Pool (T -> 1) ]
    |
    +--[ Linear(F, 1) ]
    |
    logit

    The multi-scale design replaces depth with breadth: three
    moderately deep branches (3 blocks each) at complementary
    dilation scales provide receptive field diversity across temporal
    resolutions without requiring a single very deep stack.
    Branch depth (3 blocks) and dilation schedules are architectural
    design choices fixed before hyperparameter search, not tuned
    parameters.

    Tunable hyperparameters: num_filters (F), kernel_size (k),
    dropout rate, fusion strategy.

    Ablation: M3 vs M1 isolates the contribution of multi-scale
    temporal processing.

6.5.1 Justification of the branch dilation schedules

    The three dilation schedules -- [1, 2, 4], [8, 16, 32], and
    [32, 64, 128] -- are not arbitrary. They were selected before
    hyperparameter search to satisfy four design criteria simultaneously:
    (i) each branch must sense a temporal scale that is physiologically
    meaningful for rodent ictal EEG; (ii) the three branches must
    jointly cover the full range of clinically relevant seizure
    morphologies from sub-100 ms transients to multi-second envelopes;
    (iii) the schedules must produce a continuous (gap-free) coverage
    of temporal resolutions without an excessively redundant overlap;
    and (iv) the branch receptive fields must collectively span the
    5 s segment so that no segment is classified using only sub-segment
    information.

    (a) Why three branches rather than two or four

    Two branches would force the model to compromise between either
    the spike scale and the burst scale, or the burst scale and the
    seizure-envelope scale, omitting one entire morphological family.
    Four or more branches would introduce additional redundancy
    between adjacent scales (each consecutive pair already overlaps
    by design -- see (d) below) and inflate parameter count and
    inference cost without enlarging the covered temporal range,
    because the maximum useful dilation is bounded above by the 5-s
    segment length. Three branches are the minimum number that
    distinguish the three canonical ictal morphological families
    documented in the electroencephalography literature -- sharp
    transients (spikes / polyspikes), rhythmic bursts, and sustained
    ictal evolution -- so each branch is mapped one-to-one to a
    physiologically distinct phenomenon. The mapping is reported in
    Table 6.5.1.

    (b) Why an exponential (geometric doubling) progression

    Within each branch the dilation factor doubles between consecutive
    CausalConvBlocks (d_{i+1} = 2 * d_i). This is the canonical TCN
    schedule introduced by Bai et al. (2018) and previously adopted in
    WaveNet (van den Oord et al., 2016) for the same reason: it allows
    the per-layer receptive field to grow exponentially with depth
    while parameter count grows only linearly, providing the most
    parameter-efficient route to large temporal context. Linear or
    arithmetic dilation progressions (e.g., d = 1, 2, 3, 4) would
    require many more layers (and therefore many more parameters) to
    cover the same temporal range, and would also produce uneven
    coverage -- adjacent layers would sense nearly identical scales,
    while large scales would remain unreached.

    (c) Mapping of branches to physiological time-scales

    The per-block receptive field of a CausalConvBlock with kernel
    size k and dilation d is RF_block = 1 + 2*(k-1)*d (two
    convolutions per block, Section 6.1). This per-block RF is the
    temporal window each layer effectively "sees" in the input,
    and is the quantity that must be compared against electrographic
    feature durations. At the maximum tuned kernel size k = 7, the
    per-block receptive fields evaluate as:

        Table 6.5.1 -- Per-block receptive field per branch at k=7

        Branch       Dilation   RF_block    RF_block (ms)   Sensed feature
        ------       --------   --------    -------------   ------------------------
        Branch 1     d = 1       13 samp        26 ms       individual spikes
        (fine)       d = 2       25 samp        50 ms       spike + slow wave onset
                     d = 4       49 samp        98 ms       polyspike clusters

        Branch 2     d = 8       97 samp       194 ms       short rhythmic bursts
        (medium)     d = 16     193 samp       386 ms       spike-wave complexes
                     d = 32     385 samp       770 ms       sustained burst trains

        Branch 3     d = 32     385 samp       770 ms       early ictal patterns
        (coarse)     d = 64     769 samp     1.538 s        evolving ictal rhythms
                     d = 128   1537 samp     3.074 s        full-segment envelopes

    These windows align with established electrographic feature
    durations in rodent EEG: inter-ictal spikes typically span
    20-70 ms with polyspike complexes extending to ~200 ms;
    ictal rhythmic discharges in rodent models occupy the 3-30 Hz
    band, corresponding to periodicities of ~33-333 ms, and burst
    trains commonly persist for hundreds of milliseconds to
    >1 second; tonic-clonic and absence ictal patterns evolve over
    seconds. The three branches therefore decompose the input into
    feature streams whose temporal supports correspond, by design,
    to these three documented morphological regimes rather than to
    arbitrary multi-resolution scales.

    (d) Why the schedules start at d = 1, 8, and 32

    The fine branch starts at d = 1 because spike-class transients
    occupy the finest temporal resolution available; any larger
    starting dilation would skip the spike scale entirely. The
    intermediate branch starts at d = 8 (per-block RF = 97 samples
    = 194 ms at k = 7) -- the smallest dilation at which the
    per-block RF exceeds the upper duration of a typical polyspike
    cluster, ensuring that the medium branch begins where the fine
    branch's coverage saturates. The coarse branch starts at d = 32
    (per-block RF = 770 ms at k = 7) -- the smallest dilation at
    which the per-block RF exceeds the upper duration of typical
    rhythmic burst trains, so that the coarse branch begins where
    the medium branch's coverage saturates.

    The shared dilation value d = 32 at the upper bound of Branch 2
    and the lower bound of Branch 3 is deliberate: it guarantees a
    continuous (gap-free) temporal-coverage curve across the
    medium-to-coarse transition. Without this overlap, the model
    would have a blind spot around the ~770 ms scale -- the precise
    range at which mid-duration burst trains transition into
    sustained ictal patterns. The overlap is acknowledged as the
    primary source of inter-branch redundancy that motivated the use
    of Shapley value attribution rather than leave-one-out ablation
    for per-prediction interpretability (Section 13.3).

    (e) Full-segment coverage at the cumulative branch level

    The cumulative branch-level receptive field is
    RF_branch = 1 + 2*(k-1)*sum(dilations). At k = 7 this yields 85
    samples (170 ms) for Branch 1, 673 samples (1.346 s) for
    Branch 2, and 2689 samples (5.378 s) for Branch 3. The coarse
    branch's RF slightly exceeds the 5-s segment, ensuring that
    every output time step of the coarse branch has access to the
    full temporal context of the segment at the fusion stage. The
    medium branch reaches ~27% of the segment, sufficient to span
    the longest individual burst train but not the full ictal
    evolution; the fine branch covers ~3.4% of the segment, focused
    on sub-segment transient morphology. Each branch therefore
    contributes information at a distinct hierarchical level rather
    than three nearly identical full-segment representations.

    (f) Why the dilations are fixed rather than tuned

    The dilation schedules were fixed before Optuna search and are
    treated as architectural design constants, not hyperparameters.
    Three considerations motivate this choice. First, allowing
    Optuna to vary the dilations would conflate architectural
    design decisions with hyperparameter optimisation, weakening
    the M1-vs-M3 ablation comparison: a measured M3-over-M1
    improvement would no longer be attributable to multi-scale
    processing as a concept, but to one specific tuned schedule
    that may not generalise across studies. Second, the schedules
    were chosen to map cleanly to documented seizure morphology
    timescales; tuning them on a single validation partition would
    likely produce values without a clear physiological
    interpretation, weakening the interpretability story (Section
    13). Third, every additional tunable integer in the search
    space inflates the number of trials needed for convergence;
    fixing the dilations and tuning only the orthogonal parameters
    (num_filters, kernel_size, dropout, fusion strategy) keeps the
    search tractable on the available compute budget.

7. HYPERPARAMETER OPTIMISATION
--------------------------------------------------------------------------------

Hyperparameters were optimised using the Tree-structured Parzen
Estimator (TPE) algorithm implemented in Optuna (Akiba et al., 2019).
A two-stage tuning strategy was employed: backbone architectural and
training hyperparameters were tuned first, and attention-specific
hyperparameters were tuned subsequently with the backbone architecture
hyperparameters held fixed at the values selected by the first stage.
Backbone weights were not transferred between stages: every Optuna
trial in the attention-tuning stage initialised the full network with
random weights and trained all parameters end-to-end (no freezing, no
checkpoint load). Restricting the search space to attention and
training hyperparameters keeps the second stage tractable while
allowing the backbone to co-adapt with the attention module in every
trial. This sequential design ensures that the M1-vs-M2 and M3-vs-M4
ablation comparisons share identical backbone architecture
configurations.

7.1 Common tuning protocol

    For each model, 50 Optuna trials were conducted using the TPE
    sampler with 10 initial random exploration trials, after which
    Bayesian kernel density estimation guided subsequent sampling
    (Bergstra & Bengio, 2012). Each trial trained a candidate model
    for a maximum of 20 epochs, with early stopping triggered when
    the validation macro F1-score failed to improve for 5 consecutive
    epochs. Within each trial, the AdamW optimiser (Loshchilov &
    Hutter, 2019) was employed with cosine annealing learning rate
    decay, in which the learning rate was reduced from the
    trial-specific initial value to 1% of that value over the
    20-epoch budget. Gradient clipping with a maximum norm of 1.0
    was applied at each parameter update step to stabilise training
    in deep temporal convolutional architectures.

    To reduce computational cost, a MedianPruner was configured to
    terminate underperforming trials after 3 warm-up epochs: once a
    trial's intermediate validation F1 fell below the running median
    of all completed trials, training was halted and the trial was
    marked as pruned. The pruner was inactive during the first 10
    trials to allow a sufficient baseline of completed evaluations
    for robust median estimation.

    A fixed random seed of 42 was set at the start of every trial
    to ensure reproducible weight initialisation across all
    hyperparameter configurations. During tuning, a stratified 1%
    subset of the validation partition was used for per-epoch
    evaluation, reducing validation cost while preserving the
    original class ratio (see Section 7.1.1 for the timing
    justification and sample-size analysis).

    Table 2. Common hyperparameter tuning configuration.

    Parameter               Value
    ----------------------- -------------------------------------------
    Total trials            50
    Max epochs per trial    20
    Early stopping patience 5 epochs
    Random startup trials   10
    Pruner                  MedianPruner (n_warmup_steps = 3)
    Sampler                 TPESampler (seed = 42)
    Optimiser               AdamW
    LR scheduler            CosineAnnealingLR (eta_min = lr x 0.01)
    Loss function           BCEWithLogitsLoss (pos_weight = 1.0)

    Validation subset       1% stratified (see Section 7.1.1)
    Mixed precision         AMP (FP16 on CUDA, FP32 fallback)

    is sufficient for stable F1-score ranking during hyperparameter
    optimisation. With 116 positive cases, the standard error on
    recall at an operating point of p = 0.9 is approximately 2.8%
    (sqrt(p(1-p)/n)), which is substantially smaller than the F1 gap
    typically observed between good and poor hyperparameter
    configurations. This precision is consistent with established
    practice in medical imaging and EEG literature, where
    hyperparameter selection and early stopping decisions are
    routinely based on validation sets containing fewer than 150
    positive cases (Rajpurkar et al., 2017; Roy et al., 2019).

    The 1% subset is drawn once per tuning script with a fixed seed
    (42) and is held constant across all 50 trials within that
    script, ensuring that trial-to-trial F1 differences reflect
    genuine hyperparameter effects rather than subset sampling
    variability. The full validation partition is reserved for
    (a) early-stopping and checkpoint selection during final model
    training (Section 7.6), and (b) threshold-selection analyses
    reported alongside the held-out test set. The test partition is
    never accessed during tuning.

7.1.2 Protocol parameter justifications

    Three numerical choices in the common tuning protocol -- trial
    budget (N = 50), pruner activation threshold (10 startup trials),
    and trial-level early-stopping patience (5 epochs) -- merit
    explicit justification because they jointly determine search
    coverage, compute cost, and statistical reliability.

    Trial budget (N = 50)
    ---------------------
    Two considerations bound this choice. From below, TPE-based
    optimisation requires at least a few tens of completed trials
    before the surrogate model develops a reliable preference
    distribution over good and poor configurations; empirical
    studies on similar-dimensional hyperparameter spaces report
    diminishing returns beyond approximately 30-40 trials
    (Bergstra & Bengio, 2012; Akiba et al., 2019). From above, the
    available compute budget on a shared HPC partition (13-day
    per-job walltime, mid-range GPUs) places a hard ceiling on the
    number of trials that can complete within a single job
    submission. At an empirical per-trial wall time of approximately
    five hours on the L40S partition, 50 trials consume about ten
    days of compute, which fits inside the walltime with a margin
    sufficient for occasional pruner-induced acceleration. Choosing
    fewer than 50 trials would leave the TPE sampler too close to
    its random-search startup regime; choosing more would inflate
    cost without commensurate F1 improvement.

    Pruner activation threshold (n_startup_trials = 10)
    ---------------------------------------------------
    The MedianPruner classifies a trial as underperforming when its
    intermediate validation F1 at a given epoch falls below the
    median of all previously completed trials at the same epoch.
    Reliable median estimation requires a non-trivial sample of
    completed trials; with fewer than approximately ten observations,
    the median is heavily influenced by early-trial outliers and
    pruning decisions become unreliable. Setting the activation
    threshold to ten matches the random-startup phase of the TPE
    sampler exactly, so the pruner becomes active precisely when
    the sampler begins to exploit promising regions. This avoids
    two failure modes: pruning during random exploration, which
    would discard informative observations from the search space;
    and delayed activation, which would waste compute on weak
    configurations that could have been terminated earlier. The
    n_warmup_steps = 3 setting further protects against pruning at
    epoch 1-2, when validation F1 has not yet stabilised
    (Akiba et al., 2019).

    Early-stopping patience (5 epochs within a 20-epoch budget)
    -----------------------------------------------------------
    Each trial trains for at most twenty epochs but terminates if
    the validation macro F1 fails to improve for five consecutive
    epochs. The patience value of five represents a quarter of the
    epoch budget and is large enough to traverse the short
    intermediate plateaux that arise during cosine-annealed training,
    yet small enough to release compute promptly when a trial has
    genuinely converged or is unable to make further progress.
    Larger patience values (e.g. 10) would extend each trial's
    average runtime substantially without producing meaningfully
    better final F1 estimates, while smaller values (e.g. 3) risk
    truncating trials before the cosine schedule has annealed the
    learning rate sufficiently to reach the trial's true peak
    performance. In the observed M3 study (Section 7.4.1), the
    chosen patience permitted full-budget completion for trials
    that genuinely improved across the schedule and prompt
    termination for the rest, yielding a 48 percent prune rate
    after the activation threshold.

    The four architectural hyperparameters (num_layers, kernel_size,
    num_filters, dropout) jointly determine the model's capacity to
    represent temporal patterns in the EEG signal, while the three
    training hyperparameters (learning_rate, weight_decay, batch_size)
    control how effectively the optimiser navigates the resulting loss
    landscape. All seven are tuned jointly because architectural and
    training choices interact: for example, deeper networks with more
    filters may require stronger regularisation (higher dropout or
    weight decay) to avoid overfitting, while wider networks may
    tolerate larger batch sizes without gradient noise becoming
    problematic.

    Architectural constraint: the receptive field (RF) of a TCN
    determines the number of consecutive input samples that can
    influence each output time step. For the detection of seizure
    events that unfold over at least one second of EEG, the RF
    must span a minimum of 500 samples at 500 Hz. The RF of L
    stacked CausalConvBlocks, each containing two dilated
    convolutions with exponentially increasing dilation factors
    (d = 1, 2, ..., 2^(L-1)), is given by:

        RF = 2 * (2^L - 1) * (k - 1) + 1

    where k is the kernel size and the factor of 2 accounts for
    the two convolutions per block. Hyperparameter configurations
    for which this expression evaluates to fewer than 500 samples
    are rejected before training begins (the trial is pruned
    immediately), avoiding the computational cost of a full
    20-epoch evaluation on an architecturally inadequate model.
    With num_layers restricted to [6, 9], only the single (L=6,
    k=3) combination produces RF < 500 (RF = 253 samples, 0.51 s);
    the other 11 of 12 (L, k) combinations pass, giving a 92%
    acceptance rate at the sampling stage. For example, L = 6
    with k = 7 yields RF = 757 samples (1.51 s) and is accepted.

7.3 M2: Temporal attention hyperparameter search space

    The TCN backbone hyperparameters are inherited from M1's tuning
    study (best_params.json) -- specifically num_layers, num_filters,
    kernel_size, and dropout -- and held fixed during M2's attention
    hyperparameter search. The backbone is instantiated with these
    inherited architectural hyperparameters and random weights at the
    start of every trial, and the entire network (backbone + attention
    + classification head) is trained end-to-end through AdamW. No
    parameters are frozen and no prior backbone checkpoint is loaded.
    Only attention-related and standard training hyperparameters are
    sampled by Optuna; the backbone architecture hyperparameters are
    not part of the search space.

    Restricting the Optuna search space to attention and training
    hyperparameters is a search-efficiency choice, not an ablation
    device. It reduces the dimensionality of the search from the
    full M1+attention space to five hyperparameters
    (attention_dim, attention_dropout, learning_rate, weight_decay,
    batch_size), allowing the 50-trial budget to converge more
    efficiently on attention-specific configurations, while leaving
    every trainable weight free to adapt to the attention mechanism
    in each trial.

    The M1 vs M2 ablation comparison itself takes place at the
    final-training stage (Section 7.6), not at the tuning stage.

7.6 Final model training protocol

    Each of the four ablation models (M1-M4) is trained from scratch
    on the full training partition after hyperparameter optimisation.
    The protocol is identical in structure across all four models;
    differences arise only in (a) the hyperparameters loaded from the
    corresponding tuning-output JSON and (b) the attention module
    activation for M2 and M4. A single run produces the weights,
    operating-threshold, evaluation report, and post-processing
    configuration required for downstream analysis.

7.6.1 Hyperparameter source and protocol consistency

    Each model loads its best hyperparameters from the Optuna study
    conducted in Sections 7.2-7.5:

      M1 (TCN)            : best_params.json
      M2 (TCN + Attention): best_attention_params.json
      M3 (MS-TCN)         : best_multiscale_params.json
      M4 (MS-TCN + Attn)  : best_multiscale_attn_params.json

    The hyperparameters used during training are a strict superset of
    those tuned: every Optuna-selected value is applied verbatim. No
    post-hoc hyperparameter manipulation is performed between tuning
    and training. This ensures that the reported test-set metrics
    reflect the hyperparameters selected by the validation-F1
    objective, not a subsequent hand-tuned variant.

    For reproducibility, the training scripts additionally record in
    their output JSON: the full hyperparameter dictionary, the
    training seed (42), the PyTorch and CUDA versions, the GPU model,
    the training wall-clock duration, and the git commit hash (where
    available) of the source tree at training time.

7.6.2 Optimisation

    Parameter updates use the decoupled-weight-decay variant of Adam
    (AdamW; Loshchilov & Hutter, 2019):

        theta_{t+1} = theta_t - lr * (m_hat / (sqrt(v_hat) + eps)
                                      + weight_decay * theta_t)

    Decoupled weight decay is preferred over L2 regularisation
    embedded in the gradient because the latter interacts with
    adaptive step sizes in ways that have been shown to degrade
    generalisation on deep convolutional networks. Both lr and
    weight_decay are Optuna-selected per-model.

    Learning rate follows a cosine annealing schedule
    (Loshchilov & Hutter, 2017) over the full 100-epoch budget:

        lr(t) = eta_min + 0.5 * (lr_initial - eta_min) *
                (1 + cos(pi * t / T_max))

    with T_max = 100 and eta_min = 0.01 * lr_initial. The schedule is
    stepped once per epoch. When early stopping terminates training
    before epoch 100, the cosine cycle is necessarily truncated; the
    best-F1 checkpoint (Section 7.6.6) captures the weights at the
    peak of the realised trajectory rather than the schedule endpoint.

7.6.3 Loss function and class imbalance treatment

    Training minimises the binary cross-entropy loss with logits
    (BCEWithLogitsLoss), computed on the raw pre-sigmoid output:

        L = -[ pos_weight * y * log(sigma(z))
               + (1 - y) * log(1 - sigma(z)) ]

    with pos_weight = 1.0. Class imbalance is addressed exclusively
    through offline proximity-aware downsampling of the training
    partition (see Section 5 and create_balanced_splits.py) rather
    than through loss reweighting. The resulting manifest has a
    1:2.37 ictal-to-non-ictal ratio, which is balanced enough for
    standard BCE optimisation without further correction.

    Offline downsampling is preferred over online pos_weight
    upweighting for two reasons: (i) it keeps the empirical gradient
    variance well-conditioned, whereas large pos_weight values
    amplify rare-class gradients disproportionately; (ii) it makes
    hyperparameter tuning results directly comparable across models,
    since the loss surface seen by Optuna is identical to the surface
    seen at final training.

7.6.4 Mixed-precision training

    On CUDA devices, forward passes and backward passes are wrapped
    in torch.amp.autocast("cuda") with FP16 arithmetic. Gradient
    scaling is managed by torch.amp.GradScaler, which dynamically
    adjusts a loss-scale factor to prevent FP16 gradient underflow
    while preserving the numerics of parameter updates in FP32. The
    BatchNorm statistics, softmax attention weights, and loss
    accumulation remain in FP32 internally.

    On the V100 (Volta), A100 (Ampere), and L40S (Ada) GPU nodes
    available in the HPC allocation, FP16 autocast enables Tensor-
    Core utilisation for matrix-multiply and convolution primitives,
    which reduces training wall time at no accuracy cost on models
    of this scale. On CPU fallbacks the autocast context is inactive
    and all operations remain FP32, so evaluation numerics are
    unchanged between cluster runs and any local debugging runs.

7.6.5 Gradient regularisation

    Gradient norms are clipped before each optimiser step using
    torch.nn.utils.clip_grad_norm_ with max_norm = 1.0 and L2 norm:

        if ||g||_2 > 1.0:  g <- g * (1.0 / ||g||_2)

    The clip is applied after GradScaler unscaling and before the
    optimiser step to prevent gradient explosion through the deeply
    stacked dilated convolutions. This safeguard is particularly
    relevant for M1 at high num_layers (up to 8) and M3/M4 with
    kernel_size = 7 and dilation = 128 in the coarse branch, where
    the effective depth along the coarse receptive field reaches
    6 layers of rescaling.

7.6.6 Early stopping and checkpoint selection

    Early stopping is governed by validation macro F1-score evaluated
    on a 5% stratified subset of the validation partition
    (approximately 214,908 segments: 580 ictal and 214,328 non-ictal,
    preserving the natural ictal:non-ictal prevalence of 0.27%). The
    full validation partition (4,298,154 segments) is reserved for
    the post-training pass described in Section 7.6.6a; it is not
    used for any per-epoch decision. Early-stop firing is gated by a
    minimum-epoch threshold MIN_EPOCHS_BEFORE_ES = 40: the patience
    counter is updated every epoch but cannot trigger termination
    until training has reached the cosine-schedule fine-tuning region
    (Regime B, see below). After each epoch:

        if val_macro_f1[t] > best_val_f1:
            best_val_f1 = val_macro_f1[t]
            best_epoch  = t
            epochs_no_imp = 0
            save weights to {model}_best_weights.pt
        else:
            epochs_no_imp += 1
            if t >= MIN_EPOCHS_BEFORE_ES and epochs_no_imp >= 15:
                break

    The 5% subset is constructed once at the start of each training
    run from a deterministically seeded RNG (SEED + 1) so that the
    monitor sample is identical across SLURM resubmissions. Stratified
    sampling preserves the natural class prevalence so that the
    monitor F1 reflects the deployment-relevant operating regime: a
    model selected on this subset is selected against the same
    precision-recall trade-off it will face at test time. Validation
    on the full 4.3M-segment partition is I/O-bound at approximately
    11 hours per epoch on the working storage tier, which would
    raise per-epoch wall time from ~75 minutes (training plus 5%
    monitor) to ~12 hours and would make the gated protocol
    infeasible (worst-case 55 epochs * 12 h = 27 days per model);
    the 5% subset reduces per-epoch validation cost by a factor of
    approximately twenty without altering the prevalence regime.

    Justification of the minimum-epoch gate
    ---------------------------------------

    The cosine annealing schedule (Loshchilov & Hutter, 2017) over
    T_max = 100 epochs has two qualitatively distinct phases that the
    early-stopping protocol must respect:

      Regime A -- high-LR exploration (epochs 1-~30).
        The cosine curve is nearly flat at the start: at epoch t = 17
        the learning rate has decayed only ~7% from its initial value,
        and at epoch t = 30 it has decayed ~21%. In this phase the
        optimiser takes large steps that explore the loss landscape
        broadly. Per-epoch validation F1 is volatile because the
        weights are still moving across regions of the landscape; the
        observed F1 reflects whichever region the optimiser happens
        to occupy at the end of an epoch, not a converged solution.

      Regime B -- LR-decay fine-tuning (epochs ~30-80).
        The cosine derivative steepens past the schedule midpoint:
        by epoch 40 the LR is at ~36% of its initial value, by epoch
        50 at 50%, by epoch 70 at ~19%. In this phase the optimiser
        steps shrink and the model converges into the deepest part of
        whichever basin Regime A identified. Per-epoch validation F1
        becomes more stable as variance from the optimiser shrinks
        proportionally to the LR.

    The cosine schedule is designed to deliver both regimes:
    exploration when LR is high, exploitation when LR shrinks. An
    early-stopping protocol that allows termination during Regime A
    captures only the exploration phase and therefore reports
    under-converged models -- it forfeits the fine-tuning phase the
    schedule was specifically constructed to provide.

    Empirical confirmation. A pilot final-training run of M3
    (MultiScaleTCN) under an earlier, ungated patience-10 protocol
    terminated at epoch 18 with the best-epoch monitor F1 occurring
    at epoch 8 (LR still at 99% of initial, fully inside Regime A).
    Per-epoch monitor F1 over those 18 epochs spanned the range
    0.59-0.79 with a standard deviation of approximately 0.06 -- a
    pattern consistent with high-LR exploration dynamics rather than
    convergence. The pilot result is reported here as preliminary
    methodology evidence; the production M3 run uses the gated
    protocol described below, the same protocol applied to M1, M2,
    and M4, ensuring all four ablation models are trained under
    identical conditions.

    Gate definition and operation. MIN_EPOCHS_BEFORE_ES = 40 was
    chosen to coincide with the cosine schedule reaching ~36% of its
    initial learning rate, which is the conventional onset of the
    fine-tuning regime in cosine-annealed training (Loshchilov &
    Hutter, 2017; Goyal et al., 2017). The patience counter
    epochs_no_imp is updated every epoch starting from epoch 1, but
    the termination condition is only evaluated when the gate is
    open (t >= MIN_EPOCHS_BEFORE_ES). This means:

      - During Regime A (t < 40), the model trains unconditionally
        through 40 epochs regardless of the monitor F1 trajectory.
      - From epoch 40 onward, ES applies as before with patience 15:
        if 15 consecutive epochs pass without a new monitor-F1 best,
        training terminates and the best-epoch weights are restored.

    Worst-case bound. If no improvement is observed after the gate
    opens, training terminates at epoch 40 + 15 = 55. Best-case bound
    is governed by the natural convergence of the model: training
    typically completes between epochs 50 and 80 in our setting.
    Per-model wall-time impact at ~75 minutes per epoch on the
    cluster's V100/A100/L40S partitions is approximately 50-70 hours
    in production, well within the SLURM 3-day-per-submission budget
    when combined with checkpoint resumption (Section 7.6.6 ckpt
    discussion).

    Reproducibility and fairness. Applying the same gate value to all
    four ablation models (M1-M4) ensures any observed performance
    difference between them reflects architectural variables (TCN vs.
    multi-scale TCN; with vs. without temporal attention) rather than
    differential exposure to the LR schedule's fine-tuning phase. The
    gate is therefore not a per-model hyperparameter but a fixed
    methodological constant of the ablation protocol.

    Patience justification. The patience of 15 epochs (after the
    gate) is intentionally less aggressive than the patience of 5
    used during tuning: tuning's objective is fast comparative
    ranking under MAX_EPOCHS = 20, whereas final training's objective
    is to give the cosine schedule sufficient time to anneal through
    any intermediate plateaux in the loss landscape after entering
    the fine-tuning regime. The patience increase from the original
    pilot value of 10 to 15 reflects the empirical observation that
    Regime B F1 trajectories include short non-improving stretches
    before the next best epoch, particularly for the multi-scale
    architectures with their deeper effective receptive fields.

    Two checkpoints are maintained:
      - {model}_best_weights.pt: weights at the epoch of highest
        monitor-subset macro F1. These weights are used for all
        reported test-set evaluations (Section 9).
      - {model}_latest_weights.pt: weights at the most recently
        completed epoch, overwritten each epoch, used for crash
        recovery and warm resume (not for reporting).

    All reported metrics in Section 9 are derived from the
    best-F1 weights, not the latest weights.

7.6.6a Final evaluation on the full validation partition

    After training completes (either by reaching 100 epochs or by
    early stopping), the best-epoch weights are restored and two
    additional evaluation passes are performed:

      (a) Sanity-check pass on the same 5% monitor subset. This
          re-computes macro F1 on the identical stratified sample
          used during training and compares it to best_val_f1
          recorded in the latest checkpoint. Both numbers come from
          the same subset, so a mismatch beyond floating-point
          tolerance (1e-3) signals a weight-restoration failure
          (e.g., device mismatch, state-dict corruption). This pass
          is fast (~33 minutes) because it operates on the same
          ~215K-segment subset.

      (b) Full-validation pass on the complete 4,298,154-segment
          partition. This is the only pass that touches the full
          validation set during training; its outputs (y_true,
          y_prob arrays) are the inputs to all post-training
          analyses: the three-row evaluation table (Section 7.6.11),
          smoothing/refractory/min-duration post-processing
          (Section 7.6.9), Youden's-J threshold optimisation
          (Section 7.6.10), the events-per-24-h false-alarm rate,
          and -- for M2 and M4 -- the temporal-attention saliency
          visualisations.

    All metrics reported in Section 9 (precision, recall, macro F1,
    AUROC, AUPRC, calibration, FAR, three-row table) are computed
    from the full-validation pass, not from the monitor subset. The
    monitor subset is used solely for early-stopping decisions during
    training and for the post-training weight-restoration sanity
    check; it does not appear in any reported number.

7.6.6b Numerical safety for the final-evaluation pass (FP32 forward)

    The post-training full-validation forward pass is executed in
    FP32 (use_amp = False) on all four training scripts (TCN.py,
    TCNTemporalAttention.py, MultiScaleTCN.py,
    MultiScaleTCNAttention.py). Training itself remains under AMP
    (FP16 autocast + dynamic GradScaler) for the speed and memory
    benefits documented in Section 7.6.4; FP32 applies only to the
    one-shot full-val pass after weight restoration.

    Motivation. Two distinct FP16 numerical failures during this
    pass were observed in the course of the study, each of which
    silently corrupted the y_prob array and surfaced only when
    sklearn's roc_auc_score raised ValueError: Input contains NaN:

      (i)  Input-side overflow (M3, MultiScaleTCN). A small number
           of validation segments had max |x| ~ 1e19 (post-
           preprocessing pipeline drift); these exceed the FP16
           dynamic range (max ~ 6.55e4), producing +Inf activations
           that propagate to NaN in the post-sigmoid probability.

      (ii) Attention-softmax overflow (M4, MultiScaleTCNAttention).
           Even after manifest-level filtering removed all extreme
           input segments, the attention block's logit -> exp ->
           normalise pipeline can produce +Inf in the softmax
           numerator for any attention logit > log(FP16_max) ~ 11.1,
           giving Inf / Inf = NaN at the normalisation step. This
           is an architecture-induced failure mode specific to
           softmax-attention models and is not addressed by input
           filtering.

    Both failure modes are eliminated unconditionally by running
    the final-eval forward pass in FP32, whose dynamic range
    (max ~ 3.4e38) is sufficient for both observed regimes. The
    full-validation pass typically takes ~10-15 h on V100/A100/L40S
    under FP32 (vs ~5-8 h under FP16); the additional wall time is
    negligible relative to the multi-hour-to-multi-day training
    budget and is paid only once per model.

    A complementary four-layer defence-in-depth pattern is centralised
    in eval_utils.py (SafeEEGSegmentDataset for Layer 2 input
    sanitisation, FP32 forward as Layer 3, and a per-batch
    torch.isfinite(logits).all() assertion as Layer 4) and is used by
    every *_evaluation.py test-set script in the repo. The M4 val
    artefact recovery utility (m4_event_metrics_recovery.py) consumes
    the same pattern -- it loads ms_attn_final_weights.pt, repeats
    the full-validation pass under all four protections, and emits
    every val artefact that the original training run failed to
    write, routed to OUTPUT_ROOT/val_event_metrics/ so that the parent
    MODEL4 directory is preserved.

7.6.7 End-to-end training for attention models (M2, M4)

    Both Optuna tuning (Sections 7.3, 7.5) and final training of
    M2 and M4 use end-to-end training: the entire parameter set --
    backbone and attention -- is initialised randomly and updated
    jointly through AdamW. No parameters are frozen and no prior
    backbone checkpoint is loaded at any stage. The only difference
    between tuning and final training is the search space and the
    training budget: tuning samples the five attention/training
    hyperparameters across N_TRIALS = 50 with MAX_EPOCHS = 20 and
    early-stopping patience 5, whereas final training applies the
    best-trial values for MAX_EPOCHS = 100 with patience 15.

    End-to-end training is the standard regimen for attention-
    augmented convolutional networks in the action-recognition and
    medical-imaging literature; it allows the attention module and
    backbone to co-adapt at the full representational capacity of
    the model.

    End-to-end training is also what makes the ablation comparison
    meaningful for this study. The research question targeted by
    M1 vs M2 (and equivalently M3 vs M4) is whether the
    architecture as a whole -- backbone plus attention versus
    backbone plus global average pooling -- generalises better to
    held-out subjects, not whether attention can extract additional
    signal from a frozen, pre-optimised feature extractor. To
    answer the architecture-level question, both models in each
    pair must be free to converge to their natural optima under
    identical conditions. They are therefore trained from scratch
    using shared seed, optimiser, learning-rate schedule, gradient
    clipping, AMP settings, and epoch budget; the only difference
    between paired models is the architectural variable being
    ablated. Backbone weights are not weight-shared across pairs;
    fairness is enforced through identical training protocol rather
    than identical post-training weights, matching the convention
    of contemporary deep-learning ablation studies.

7.6.8 Deterministic reproducibility

    Before each training run, reproducibility is enforced by:

        random.seed(42)
        numpy.random.seed(42)
        torch.manual_seed(42)
        torch.cuda.manual_seed_all(42)

    DataLoader workers inherit worker-specific derived seeds through
    the PyTorch worker_init_fn pattern. For the cuDNN backend,
    benchmark mode is disabled and deterministic algorithms are
    enabled where supported (torch.backends.cudnn.deterministic = True,
    torch.backends.cudnn.benchmark = False). Non-deterministic atomic
    operations in certain cuDNN primitives (e.g., dilated convolutions
    with reverse-pass scatter operations) may introduce negligible
    run-to-run variability at the 1e-6 level in gradients; this has
    no measurable effect on validation F1 at the precision reported
    in Section 9.

7.6.9 Post-processing of predictions

    Raw per-segment sigmoid probabilities are transformed into
    event-level detections through three sequential stages applied
    identically to all four model variants with fixed parameter
    values. Only the decision threshold may differ between models
    (Section 7.6.10); the smoothing window, refractory period, and
    minimum duration are held constant across all comparisons, so
    inter-model differences reported in Section 9 reflect model
    architecture rather than post-processing tuning.

    Stage 1 -- Probability smoothing
    --------------------------------
    A uniform moving-average kernel of width SMOOTHING_WIN = 3
    segments is convolved with the raw sigmoid probability stream
    BEFORE thresholding:

        smoothed_probs = (1/3) * (p[t-1] + p[t] + p[t+1])
        smoothed_preds = 1 if smoothed_probs >= tau else 0

    The convolution uses mode="same" to preserve segment-to-segment
    1:1 alignment. Smoothing suppresses isolated single-segment
    probability spikes caused by transient artefacts (movement,
    electrode noise), which produce a localised peak that is
    averaged down by the low-probability neighbouring segments. A
    W = 3 window was selected as the smallest odd-length kernel
    that performs meaningful averaging while minimising temporal
    smearing of genuine short-duration seizures.

    Boundary uncertainty introduced by the smoothing stage is
    bounded by floor(W/2) * step_sec = 1 * 2.5 s = +/- 2.5 s for
    event onset and offset timing. This is clinically acceptable
    for seizure detection, where onset-time resolution to the
    nearest few seconds is sufficient for downstream clinical
    interpretation.

    Stage 2 -- Minimum duration filter
    ----------------------------------
    Candidate event runs shorter than MIN_EVENT_SEC = 25.0 seconds
    are discarded BEFORE the refractory-period merge step. This
    ordering (min-duration first, refractory merge second) matches
    the standard convention in clinical seizure-detection pipelines
    (Saab et al. 2020; Tang et al. 2022) and was confirmed
    empirically on this dataset to Pareto-dominate the alternative
    (refractory-then-min) on both M3 and M4, across both val and
    test partitions, at every MIN_EVENT_SEC value tested (see
    operating-point selection subsection below).

    The MIN_EVENT_SEC = 25.0 s threshold was selected with two
    independent lines of evidence converging on the same value:
    (i) it sits just below the 25th percentile of the empirical
    seizure-duration distribution (Q1 = 32.3 s, median = 42.6 s,
    mode-bin = 30-35 s, computed over 4 459 expert-annotated
    seizures across 101 mice -- Figure X); (ii) it lies at the
    Pareto knee of the validation recall-vs-event-FAR/hr curve,
    beyond which additional FAR reduction starts to cost recall
    disproportionately (Figure Y). Both lines of evidence are
    detailed in the operating-point subsection below.

    Stage 3 -- Refractory-period merging
    ------------------------------------
    Surviving event pairs separated by gaps shorter than
    REFRACTORY_SEC = 30.0 seconds are merged into a single event.
    This corrects for transient probability dips during a single
    underlying seizure (for example, a brief period of attenuated
    ictal amplitude mid-event) that would otherwise be counted as
    two distinct alarms. The 30-second threshold is consistent
    with standard practice in automated seizure-detection
    pipelines (Shoeb & Guttag, 2010).

    Parameter summary
    -----------------
    Parameter              Value       Rationale
    --------------------- ----------- -----------------------------
    SMOOTHING_WIN          3 segments  Suppress isolated artefact spikes
    MIN_EVENT_SEC          25.0 s      Discard sub-clinical events; below
                                        Q1 of annotated seizure-duration
                                        distribution; Pareto knee on val
    REFRACTORY_SEC         30.0 s      Merge fragmented single-seizure runs
    Stage order            min-duration first, refractory second
                           (Saab 2020; Tang 2022; empirically Pareto-
                           dominant on M3 and M4, val and test)

    The three-stage pipeline converts segment-level predictions
    (of which there can be many per minute due to 50% segment
    overlap) into a clinician-facing alarm stream in which a single
    alarm corresponds to a single contiguous detected event of
    clinically plausible duration. This event-level view is the
    quantity actually experienced by a monitoring clinician and is
    the basis for the event-level false-alarm-rate metric reported
    alongside segment-level metrics in Section 9.

    Operating-point selection -- empirical justification
    ----------------------------------------------------
    The two post-processing operating-point choices -- (a) the
    order of Stage 2 and Stage 3, and (b) the value of
    MIN_EVENT_SEC -- were jointly selected via a 2 x 5 grid sweep
    on the validation partition, with confirmation on the held-out
    test partition (no test-set re-tuning was performed). The sweep
    covered order ∈ {refractory-then-min, min-then-refractory} ×
    MIN_EVENT_SEC ∈ {10, 15, 20, 25, 30} s, applied identically to
    M3 (MultiScaleTCN) and M4 (MultiScaleTCN + Attention) on
    cached per-mouse-chronological prediction streams. Results are
    summarised in Figure Y (val vs test panels, two orderings per
    panel) and the underlying numbers are tabulated in
    comparison_val_vs_test.csv alongside each model's evaluation
    artefacts.

    Pareto dominance of min-then-refractory. At every value of
    MIN_EVENT_SEC and on both partitions of both models, the
    min-duration-then-refractory ordering yielded a strictly
    Pareto-better recall-vs-event-FAR/hr operating point than the
    refractory-then-min alternative. For example, at the selected
    MIN_EVENT_SEC = 25 s on the test partition: M3 precision 0.38
    -> 0.50, F1 0.54 -> 0.65, FAR/hr 0.151 -> 0.091 (-40%); M4
    precision 0.27 -> 0.41, F1 0.42 -> 0.57, FAR/hr 0.256 -> 0.130
    (-49%); recall reduction in both cases was <= 2 percentage
    points. This direction-of-effect is consistent with the
    intuition that min-duration filtering ahead of refractory
    merging eliminates short artefactual bursts before they can be
    chained into longer apparent events.

    Pareto-knee selection of MIN_EVENT_SEC = 25 s. Within the
    min-then-refractory ordering, the marginal trade-off ratio
    Delta(event-FAR/hr) / Delta(recall) per increment of
    MIN_EVENT_SEC was favourable at 15 -> 20 s (>= 2.0 on all four
    partition-model combinations) and 20 -> 25 s (>= 1.5), then
    collapsed sharply at 25 -> 30 s (M3-val 0.12, M3-test 0.33,
    M4-val 0.77, M4-test 0.75). MIN_EVENT_SEC = 25 s therefore
    represents the right edge of the favourable-trade-off regime,
    consistent with the recall-vs-FAR Pareto plot showing a clear
    bend between 25 s and 30 s on all four panels.

    Empirical distribution support. Independent of the model-side
    Pareto curve, MIN_EVENT_SEC = 25 s is well-supported by the
    annotated seizure-duration distribution itself. Across all
    4 459 expert-annotated seizures in the 101-mouse study cohort,
    the lower quartile (Q1) is 32.3 s -- the 25 s threshold thus
    sits 7.3 s below the lower quartile, leaving 89.2% of
    annotated seizures unambiguously above the cutoff. The median
    is 42.6 s and the modal duration bin is 30-35 s (n = 557 of
    4 459), so 25 s does not bisect the dominant seizure
    morphology cluster. At the alternative cutoff of 30 s,
    19.5% of annotated seizures fall below the threshold, almost
    double the 10.8% at-risk count at 25 s. The 25 s value
    therefore preserves clinical sensitivity (validation event
    recall remained >= 0.94 on both M3 and M4 after the filter)
    while still aggressively suppressing the short-duration false
    alarm population that dominates the raw classifier's FAR
    budget.

    Generalisation to test. Application of the selected operating
    point (order = min-then-refractory; MIN_EVENT_SEC = 25 s) to
    the held-out test partition without re-tuning yielded the
    Section 9 headline numbers. The Pareto ranking observed on
    val held on test (Figure Y bottom row), confirming that the
    selection is not an artefact of validation-set tuning.

    Per-mouse chronological organisation
    ------------------------------------
    Event detection is performed independently for each mouse,
    operating on segments arranged in true chronological order
    relative to that animal's recording start. Two pieces of
    metadata enable this organisation:

      1. The chronology file {mouse_id}_chronology.npz, produced
         once per mouse by deterministically replaying the
         preprocessing grid walk against the corresponding Excel
         seizure annotation file. For each grid position it
         records (chrono_idx, t_start_sec, label) and the .npy
         filename the preprocessing pipeline would have produced.

      2. The chronology-enriched splits manifest
         data_splits_nonictal_sampled_filtered_enriched.json,
         which augments each val/test record with mouse_id,
         chrono_idx, and t_start_sec joined from (1).

    At evaluation time the per-mouse prediction stream is sorted
    by chrono_idx so that segment k+1 in the stream is exactly
    step_sec = 2.5 s after segment k in the original recording.
    Smoothing, run detection, refractory merging, and
    minimum-duration filtering all operate on this
    chronologically-ordered per-mouse stream; events cannot span
    different animals.

    Within each mouse, surviving segments are partitioned into
    contiguous chunks where consecutive chrono_idx values differ
    by exactly 1 (delta == 1). A delta > 1 indicates one or more
    intermediate segments removed by the upstream Layer 1
    amplitude filter (Section 7.4); the chunk boundary at that
    gap prevents events from extending across a real-time
    discontinuity. Each chunk is processed as a self-contained
    sub-recording through Stages 1-3.

    Event-to-ground-truth matching (any-overlap rule)
    -------------------------------------------------
    Each post-processed predicted event for a mouse is matched
    against that mouse's annotated seizure intervals (the same
    Excel intervals consumed by the preprocessing labeller and
    by the chronology builder). The matching rule is any-overlap:
    a predicted event P is associated with a ground-truth seizure
    GT if P.start_sec < GT.end_sec and P.end_sec > GT.start_sec.

      True positive  (TP) -- a GT seizure with at least one
                             overlapping predicted event.
      False positive (FP) -- a predicted event with no overlapping
                             GT seizure (a false alarm).
      False negative (FN) -- a GT seizure with no overlapping
                             predicted event (a missed seizure).

    A single predicted event spanning two close-together real
    seizures is credited to each as a separate TP, preserving
    recall as a per-seizure detection rate rather than a
    per-prediction matching rate. This rule is standard in the
    seizure-detection literature (Shoeb 2009; Truong et al. 2018).
    Consequently, TP + FN equals the total number of ground-truth
    seizures, while TP + FP may exceed the total number of
    predicted events when single predictions overlap multiple
    seizures.

    Detection latency for each TP is defined as the start time
    of the first overlapping predicted event minus the GT
    seizure-onset time, computed in seconds. Negative latencies
    indicate the model's first positive prediction precedes the
    annotated onset (consistent with conservative annotation
    boundaries).

    Event-level metrics
    -------------------
    Per partition (val and test), the following event-level
    metrics are aggregated across all animals:

        Event Precision  = TP / (TP + FP)
        Event Recall     = TP / (TP + FN)              (sensitivity)
        Event F1         = 2 PR / (P + R)
        Event FAR/hr     = FP / non_ictal_hours
        Mean latency     = mean(latency_per_TP)        (seconds)

    The non-ictal-hour denominator is computed as the total
    number of surviving non-ictal segments multiplied by
    step_sec = 2.5 s and divided by 3600. This corresponds to
    the unique wall-clock recording duration each segment
    contributes under 50% overlap (segment k covers seconds
    k*step_sec to k*step_sec + segment_len_sec; consecutive
    segments add only step_sec of new wall-clock time). FAR/hr
    is therefore expressible as false alarm events per hour of
    real recording, not per hour of segment-coverage time.

    Event-level metrics complement the segment-level
    classification metrics (Row 1 / Row 2; see Section 7.6.11).
    Segment-level metrics characterise the per-window classifier;
    event-level metrics characterise the deployable alarm system
    actually experienced by a clinician. Event-level recall and
    FAR/hr are the principal headline quantities for clinical
    deployment claims.

    Note on event-level true negatives. Event-level TN, accuracy,
    and specificity are not well-defined because there is no
    natural unit for "a non-event period correctly identified as
    a non-event" without an arbitrary windowing choice. We
    therefore report event-level TP, FP, FN, Precision, Recall,
    F1, FAR/hr, and detection latency, in line with the
    convention in seizure-detection papers (Shoeb 2009; Roy et
    al. 2019; Tang et al. 2021), and rely on segment-level TN /
    accuracy / specificity for those quantities.

7.6.10 Operating-point selection (Youden's J)

    Following training, three operating thresholds are evaluated
    on the validation partition:

        Threshold 0.5 (raw, no post-processing)
        Threshold 0.5 (with post-processing from Section 7.6.9)
        Optimal threshold (with post-processing)

    The optimal threshold is selected to maximise Youden's J
    statistic (Youden, 1950):

        J(tau) = sensitivity(tau) + specificity(tau) - 1
               = TPR(tau) - FPR(tau)

    Youden's J is chosen as the selection criterion for three reasons:
    (i) it is threshold-independent in its formulation but yields a
    single-valued optimum; (ii) it weights sensitivity and specificity
    equally, which is appropriate for seizure detection where both
    missed seizures (clinical harm) and false alarms (clinician
    fatigue) are costly; (iii) it is invariant to prevalence, so the
    selected threshold generalises from the validation partition to
    the held-out test partition despite their differing ictal ratios.

    The selected threshold tau* and the underlying ROC traversal are
    saved to {model}_optimal_threshold.json and re-used verbatim at
    test time; no threshold re-selection occurs on the test set.

7.6.11 Three-tier evaluation reporting

    For each of the four models, Section 9 reports three rows of
    metrics corresponding to the progressive application of the
    decision rule:

        Row 1: raw per-segment predictions at tau = 0.5
               (isolates pure model output)
        Row 2: post-processed predictions at tau = 0.5
               (isolates post-processing contribution)
        Row 3: post-processed predictions at tau = tau*
               (final operating configuration)

    This three-tier reporting allows reviewers to attribute observed
    improvements to (a) the model architecture itself, (b) the
    morphological post-processing, or (c) the calibrated operating
    threshold, rather than conflating all three. Row 3 is the
    configuration used for all inter-model comparisons in the
    ablation analysis.

    Per-row score for AUROC and PRAUC. Threshold-independent metrics
    (AUROC and PRAUC) require a continuous score. For Row 1 the
    continuous score is the raw post-sigmoid probability y_prob from
    the model. For Row 2 and Row 3 the continuous score is the
    post-processing-smoothed probability y_prob_smoothed produced by
    Stage 1 of the post-processing pipeline (a moving-average kernel
    of width SMOOTHING_WIN = 3 segments applied to y_prob, see
    Section 7.6.9). The smoothed score is the same continuous quantity
    that the threshold tau is applied to, so reporting AUROC/PRAUC on
    y_prob_smoothed produces a model-quality ranking that reflects
    the deployed pipeline's discrimination rather than the raw
    pre-smoothing output. AUROC/PRAUC values for Row 2 and Row 3 are
    numerically identical because both use the same smoothing kernel
    (only the threshold differs); they will typically differ slightly
    from Row 1 values, with the smoothed score giving marginally
    higher AUROC/PRAUC because single-segment noise spikes that hurt
    raw-y_prob ranking are attenuated by the moving average.

    Per-row classification reports. For each of Row 1, Row 2, Row 3,
    a JSON file
    <model>_classification_report_row{1,2,3}.json
    is written. The base content is the standard scikit-learn
    classification report (per-class precision, recall, F1-score, and
    support, plus accuracy and macro/weighted averages), augmented
    with three top-level keys -- auroc, prauc, specificity --
    computed under the per-row scoring convention above. Each report
    is therefore self-contained: a reader does not need to
    cross-reference the three-row CSV to obtain threshold-independent
    metrics.

    Row 3 retirement. Row 3 (post-processed predictions at the
    threshold-optimised operating point tau*) has been retired from
    the current report version. The threshold-optimisation objective
    was changed from Youden's J to F1 partway through the study
    (Section 7.6.10) because the Youden operating point degenerated
    on this dataset's ~0.27% ictal prevalence (tau* = 0.10 yielded
    precision 7.4%); with the F1 objective Rowl 3 collapses to an
    operating point that is empirically very close to Row 2's
    tau = 0.5 while adding an extra threshold-sweep step that
    overfits tau to the validation partition. All reported numbers
    therefore use the Row 1 + Row 2 schema only, with Row 2 (post-
    processed at tau = 0.5) as the canonical operating configuration
    for inter-model comparisons. The threshold-sweep code path is
    kept in the source as commented scaffolding so that Row 3 can
    be re-enabled if a future dataset warrants it.

    FAR/hr denominator. Segment-level FAR/hr is reported in the
    corrected form only (denominator = n_non_ictal_segs x step_sec
    / 3600, where step_sec = 2.5 s is the unique wall-clock time
    each segment contributes under 50% segment overlap). An earlier
    "BROKEN" column that multiplied by segment_len_sec = 5.0 s
    (and so under-reported FAR/hr by 2x) was retained transiently
    in audit JSONs during the migration; it has now been dropped
    from all output schemas. Event-level FAR/hr uses the same
    step_sec-based denominator over per-mouse non-ictal hours
    (Section 7.6.9).

7.6.12 Compute budget and wall-clock cost

    Empirically observed on the HPC cluster (V100-PCIE-16GB and
    NVIDIA L40S partitions):

      Tuning (50 trials x ~10 epochs at 1% val subset):
        M1: ~2.5 days on L40S (~8.1 min/epoch sustained)
        M3: ~3.0 days on V100 (~10-12 min/epoch sustained)
        M2/M4 attention-only tuning: ~1.0 day each

      Final training (gated patience protocol: MIN_EPOCHS_BEFORE_ES = 40,
      ES_PATIENCE = 15, 5% stratified per-epoch monitor, single full-
      val pass at end, see Section 7.6.6):
        M1-M4: 50-70 hours per model on a single A100/V100.
        Per-epoch cost is dominated by data-loader I/O on the 220K-
        segment training partition (~42 min) plus 5% monitor
        evaluation (~33 min), giving ~75 min/epoch. The minimum-epoch
        gate forces unconditional training through 40 epochs (~50 h);
        post-gate, ES-patience-15 typically terminates training
        between epochs 50 and 80 depending on the model's natural
        convergence point. The single post-training full-validation
        pass adds a further ~11 h.

        every epoch (rather than via the 5% monitor + final-pass

        ~10-12 GPU-days per model serially gives ~40-50 GPU-days

7.6.13 Event-level attention saliency stratified by detection outcome

    Motivation. The class-averaged temporal-attention saliency described
    in Section 6.4.4 contrasts mean alpha_t between ictal and non-
    ictal segments and answers the question "where inside a 5-second
    window does the model attend, on average, for each class?". It
    does not, however, distinguish between attention profiles for
    seizures the model detected correctly (true positives), false
    alarms (false positives), and seizures the model missed (false
    negatives). For interpretability of the deployed system -- and
    for diagnosing failure modes -- it is the per-outcome attention
    profile that is most informative: a true-positive profile that
    concentrates shortly after seizure onset, a false-positive
    profile that concentrates on a different, transient feature, and
    a false-negative profile that is flat (the model never "looked
    at" the missed seizure) jointly characterise the model's
    behaviour at the event level. This subsection describes the
    methodology used to compute and aggregate that per-outcome
    saliency on both validation and test partitions
    (event_attention_saliency.py).

    7.6.13.1 Per-window attention is a window-relative signal

    The temporal-attention layer in MultiScaleTCNWithAttention
    produces, for each input window of length WIN_LEN = 2,500
    samples (5 s at FS = 500 Hz), a vector alpha_t of length T such
    that sum_t alpha_t = 1. The MultiScaleTCN backbone applies
    dilated causal convolutions with no stride and no pooling, and
    fuses the three branches with a 1x1 convolution; the temporal
    dimension is therefore preserved end-to-end, so T = WIN_LEN =
    2,500 and attention is already at raw EEG sample resolution. No
    upsampling between attention and input timescales is required.

    7.6.13.2 Per-event windows are 50%-overlapped, requiring overlap-
    add to reconstruct a sample-resolution saliency timeline

    The segmentation grid uses STEP = 1,250 samples (2.5 s) with
    WIN_LEN = 2,500 samples (5 s), so any interior recording sample
    is covered by exactly two windows. Naively concatenating per-
    window saliency vectors along the recording timeline would
    double-count every interior sample. The correct reconstruction
    is overlap-add with count normalisation. For each window w with
    start sample t_w and saliency vector alpha_w[0..WIN_LEN-1],
    accumulate

        S[t_w + k] += alpha_w[k]
        C[t_w + k] += 1                    for k = 0..WIN_LEN-1

    over all windows in the mouse. The continuous saliency stream is
    then

        saliency[t] = S[t] / C[t]    where C[t] > 0,

    which is the mean of the per-window attention values that
    physically cover sample t. Mean -- not sum -- so the two
    contributions at every interior sample are not double counted.
    The reconstruction is performed independently per mouse and per
    filter-gap-free chunk (using split_into_chunks from eval_utils),
    never bridging across recordings or across artefact-removed
    segments.

    7.6.13.3 Event source: post-processed events define WHERE; raw
    attention defines WHAT

    The TP / FP / FN labels under which saliency crops are
    stratified come from the canonical event_details_row2.csv bundle
    (per Section 7.6.9 the row-2 events are the post-processed event
    list -- smoothing -> min-duration filter -> refractory merge --
    that the deployed system would emit). TPs and FPs are read
    directly from the CSV via the is_true_alarm flag. FNs are not
    persisted in event_details.csv because the canonical schema
    holds predicted events only; they are re-derived at runtime by
    re-loading the seizure annotations and calling
    match_events_to_ground_truth(predicted, gt_intervals), whose
    unmatched-GT output is the FN set. The matching rule is the
    same any-overlap convention used throughout Section 7.6.9, so
    no inconsistency can be introduced between the saliency
    analysis and the operational evaluation.

    The attention values used to populate S in 7.6.13.2 are the raw
    alpha_t tensor returned by get_attention_weights, with no
    smoothing, thresholding, or post-processing applied. The
    distinction is deliberate: post-processing tells us which events
    to interpret (the deployed system's operational output); the raw
    attention values are what the model actually attended to inside
    each event. Filtering or smoothing the attention values before
    visualisation would obscure exactly the model-internal focus
    that interpretability is meant to reveal.

    7.6.13.4 Window selection and compute

    The full test partition contains 9,753,796 segments; running
    attention extraction on all of them and materialising the
    resulting (9.75M, 2,500) float32 tensor requires ~97 GB of host
    RAM, which exceeded the node's memory in an earlier evaluation
    pass. The corrected pipeline performs attention extraction on
    only the windows whose 5-second span overlaps a TP, FP, or FN
    interval; for the M4 test set this reduces the forward-pass
    workload from ~9.75M to ~20,000 windows (~0.2%) and runtime
    from ~22 hours to ~15-30 minutes on a V100. Window selection
    uses the enriched manifest's t_start_sec field directly and the
    inclusion test wt < event_start + MIN_EVENT_SEC AND wt +
    SEGMENT_SEC > event_start.

    The per-mouse working set is bounded: the attention cache for
    one mouse holds at most a few thousand 2,500-sample float32
    vectors (~tens of MB); the per-event accumulator arrays are
    CROP_LEN_SAMPLES = MIN_EVENT_SEC * FS = 12,500 samples (~50 KB
    each). Memory therefore stays under 1 GB regardless of partition
    size.

    7.6.13.5 Aggregation: align at onset, truncate to MIN_EVENT_SEC,
    pool across mice

    Each event crop is constructed by overlap-add on a per-event
    local accumulator: for each event with start sample t_e the
    accumulators S_e and C_e of length CROP_LEN_SAMPLES are zero-
    initialised; every overlapping window contributes alpha[src_lo:
    src_hi] into S_e[tgt_lo:tgt_hi] (with src/tgt indices chosen to
    intersect the window's WIN_LEN span with the event's [0,
    CROP_LEN_SAMPLES) range), and the per-sample mean S_e / max(C_e,
    1) is the crop. Samples that fall outside the union of
    overlapping windows are recorded as NaN so they can be masked
    out at aggregation time.

    Crops are pooled across all mice within each class. Aggregation
    is NaN-aware: mean and standard error of the mean are computed
    via nanmean and nanstd along the event axis, so partially-
    covered tails do not bias the curve. Onset alignment plus
    truncation to MIN_EVENT_SEC (25 s, the minimum post-processed
    event duration enforced by the row-2 pipeline) guarantees that
    every event contributes equally to every sample of the resulting
    curve, removing the need for resampling-to-fixed-length
    normalisation and preserving the absolute time axis. The chosen
    truncation makes the analysis comparable across events of widely
    differing durations without distorting the per-event temporal
    structure: every event in the row-2 pipeline is, by construction,
    at least MIN_EVENT_SEC seconds long.

    7.6.13.8 Reading guidance for the paper

    For the discussion section, the three curves are most useful
    when read together. A TP curve that rises shortly after the
    aligned t = 0 onset and decays toward the tail evidences early-
    onset detection, supporting the architectural claim that
    temporal attention captures seizure-relevant dynamics
    (Section 6.4.4). An FP curve whose peak is shifted relative to
    the TP curve indicates that the model's false alarms are not
    "weak versions of true detections" but a temporally distinct
    failure mode -- typically attention concentrating on a high-
    amplitude transient that lacks the post-onset structure of a
    genuine ictal evolution. An FN curve that is flat or low across
    the entire MIN_EVENT_SEC window indicates that the model
    assigned little attention to the GT-annotated region; this is
    consistent with subthreshold ictal morphology (electrographic
    seizures with low spectral power or atypical waveform), which
    is the canonical hard case for surface-EEG seizure detection.

9. CLASS IMBALANCE MITIGATION
--------------------------------------------------------------------------------

9.1 Uniform random downsampling (baseline approach)

    In the initial experimental configuration, non-ictal segments were
    downsampled to a 1:4 ictal-to-non-ictal ratio using stratified
    random sampling within each subject (random seed = 42). This
    procedure yielded a training corpus of 65,510 ictal and 262,040
    non-ictal segments (327,550 total). The binary cross-entropy loss
    function (BCEWithLogitsLoss) was configured with pos_weight = 1.0,
    as the offline downsampling served as the sole mechanism for class
    imbalance correction.

9.2 Proximity-aware downsampling (adopted approach)

    To better exploit informative training examples, a proximity-aware
    sampling strategy was subsequently adopted. Non-ictal segments were
    partitioned into two categories based on their temporal distance to
    the nearest annotated seizure boundary:

    (a) Near-seizure segments (distance <= 60 s). All non-ictal segments
        falling within a +/-60-second margin of any seizure onset or
        offset were retained in full. These peri-ictal segments
        encompass pre-ictal build-up activity, post-ictal suppression,
        and transitional EEG patterns that are morphologically proximal
        to ictal discharges (Litt & Echauz, 2002) [VERIFY EXACT QUOTE
        BEFORE SUBMISSION]. As the most challenging examples for a
        binary classifier, they contribute disproportionately to
        gradient-based learning, consistent with the principle of
        hard-example mining (Shrivastava et al., 2016) [VERIFY EXACT
        QUOTE BEFORE SUBMISSION].

    (b) Far-from-seizure segments (distance > 60 s). A random subsample
        comprising 5% of the near-seizure count was drawn from the
        remaining non-ictal pool. This preserves representational
        diversity across background EEG states (e.g., quiet sleep,
        active waking, grooming artefacts) while preventing the training
        corpus from being dominated by easily classifiable examples
        that yield diminishing gradient signal after the initial
        training epochs (Bengio et al., 2009) [VERIFY EXACT QUOTE
        BEFORE SUBMISSION].

    The 60-second margin was chosen to capture the temporal extent of
    peri-ictal phenomena observed in rodent models of epilepsy, where
    pre-ictal electrographic changes and post-ictal depression typically
    span tens of seconds (Luttjohann et al., 2009) [VERIFY EXACT QUOTE
    BEFORE SUBMISSION].

    The resulting balanced training manifest was generated once offline
    and reused without modification across all hyperparameter tuning and
    final model training runs. The binary cross-entropy loss pos_weight
    remained at 1.0, with the offline sampling serving as the sole
    imbalance correction mechanism.

    9.3 Final balanced training corpus

    Application of the proximity-aware strategy to the 72 training
    subjects produced the following corpus:

    Table 5. Final balanced training corpus composition.

    Component                           Count       Proportion
    ---------------------------------   ---------   -----------
    Ictal segments (all retained)       65,510      29.7%
    Non-ictal near-seizure (<=60s)      147,756     67.0%
    Non-ictal far-sampled (5% of near)  7,388       3.3%
    Extreme segments removed            1           --
    ---------------------------------   ---------   -----------
    Total training segments             220,653     100.0%

    The final ictal-to-non-ictal ratio is 1:2.37 (compared to the
    original 1:438 raw ratio and the 1:4 uniform-downsampling ratio).
    The corpus is 33% smaller than the uniform-downsampling approach
    (220,653 vs 327,550 segments), reducing training time while
    increasing the concentration of informative hard negatives:
    near-seizure segments now constitute 95.3% of the non-ictal class,
    compared to an estimated 5-10% under uniform downsampling.

    Across the 72 training subjects, 2,881 seizure events were
    annotated (mean 40.0 seizures per subject, range 1-178). This
    biological heterogeneity is preserved in the balanced manifest:
    per-subject segment counts scale with seizure burden, ensuring
    that high-seizure subjects contribute proportionally more
    near-seizure hard negatives.

    The manifest (data_splits_nonictal_sampled.json) is generated

10. DATA PROCESSING PIPELINE
--------------------------------------------------------------------------------

The end-to-end data processing pipeline proceeds through four stages:

Stage 1: Signal preprocessing and segmentation
    Raw EDF recordings from 102 subjects are preprocessed (notch
    filtering, baseline correction, robust z-score normalisation) and
    segmented into 5-second windows with 50% overlap. Each segment is
    labelled as ictal or non-ictal and saved as an individual .npy file.
    Preprocessing is distributed across five parallel batch jobs.

Stage 2: Partition manifest generation
    All five training data directories, the validation directory, and
    (when available) the test directory are scanned to produce a single
    JSON manifest (data_splits.json) containing absolute file paths and
    labels for all 33 million segments. A subject-level leakage check
    is executed to verify partition integrity.

Stage 3: Balanced corpus construction
    The training partition of data_splits.json is processed by an
    offline script (create_balanced_splits.py) that: (i) excludes
    subject m254, (ii) removes six amplitude-anomalous segments,
    (iii) classifies non-ictal segments as near-seizure or
    far-from-seizure, and (iv) applies proximity-aware downsampling.
    The output (data_splits_nonictal_sampled.json) serves as the
    training manifest for all subsequent experiments. The validation
    partition is passed through unmodified.

Stage 4: Model development
    Hyperparameter tuning (4 scripts) and final model training
    (4 scripts) load the balanced manifest directly. No further
    downsampling, filtering, or data manipulation is performed at
    training time.

The following measures were implemented to ensure full reproducibility
of all experimental results:

(i)   Deterministic seeding. A fixed random seed (42) was set for
      Python's random module, NumPy, and all PyTorch random number

      input EDF and annotation files.

      appears in more than one partition.

      in JSON manifests generated once and reused across experiments.
      The original .npy segment files are never modified, deleted, or
      moved by any downstream script, preserving the complete dataset
      for alternative analyses (e.g., self-supervised learning).

      2.5.1 with CUDA 11.8 on NVIDIA V100, A100, and L40S GPUs
      managed by the Slurm workload scheduler.

ADDENDUM A: GLOSSARY OF DEEP LEARNING CONCEPTS
================================================================================

This addendum provides intuitive explanations of the deep learning
concepts used throughout this report, aimed at readers who may be
new to the field.

A.1 Uniform vs weighted averaging (pooling vs attention)

    After a convolutional network processes a 5-second EEG segment,
    it produces a feature vector h_t at every time step t = 1, ..., T
    (where T = 2,500 at 500 Hz). Think of each h_t as a summary
    description of "what the EEG looks like" at that moment in time.

    The problem: the classifier expects a single fixed-size input,
    but we have 2,500 of these descriptions. We need to collapse
    them into one.

    GLOBAL AVERAGE POOLING (uniform averaging):
        z = (h_1 + h_2 + ... + h_T) / T

        Every time step contributes equally. Time step 1 counts as
        much as time step 2,500. This is like reading a 5-second
        EEG epoch and summarising it by averaging every moment
        equally -- no moment is considered more important than
        another.

        Used in: M1 (TCN) and M3 (Multi-Scale TCN).

    TEMPORAL ATTENTION (weighted averaging):
        c = alpha_1*h_1 + alpha_2*h_2 + ... + alpha_T*h_T

        Each time step gets its own learned weight alpha_t. The
        model learns from the data which moments are most
        informative for detecting seizures. If a seizure starts
        at time step 1,500, the model might assign alpha_1500 = 0.3
        (high attention) while giving alpha_100 = 0.001 (almost no
        attention) to a quiet background period.

        The weights alpha_t are non-negative and sum to 1 (enforced
        by the softmax function), so this is a weighted average --
        just not a uniform one.

        Used in: M2 (TCN + Attention) and M4 (Multi-Scale TCN +
        Attention).

    WHY THIS MATTERS: if seizure-discriminative EEG patterns are
    concentrated in a specific part of the 5-second window (e.g.,
    the onset), uniform averaging dilutes that signal with 4 seconds
    of uninformative background. Attention can amplify the onset and
    suppress the background, producing a cleaner signal for the
    classifier. The ablation study tests whether this learnable
    focusing actually improves detection accuracy.

A.2 Logit, sigmoid, and probability

    A logit is the raw, unbounded output of the classification head
    -- a single number that can range from negative infinity to
    positive infinity. It represents the model's "unnormalised
    confidence" that the input is a seizure.

        logit = -3.0  ->  model is fairly confident: NOT a seizure
        logit =  0.0  ->  model is uncertain (50/50)
        logit = +5.0  ->  model is very confident: IS a seizure

    The sigmoid function squashes the logit into the range [0, 1],
    making it interpretable as a probability:

        p = 1 / (1 + exp(-logit))

        logit = -3.0  ->  p = 0.047  (4.7% chance of seizure)
        logit =  0.0  ->  p = 0.500  (50% chance)
        logit = +5.0  ->  p = 0.993  (99.3% chance)

    A threshold (default 0.5) is then applied: if p >= 0.5, the
    segment is classified as ictal; otherwise, non-ictal.

A.3 Loss function

    The loss function measures how wrong the model's prediction is
    for a single training example, producing a number that the
    optimiser tries to minimise.

    Binary cross-entropy (BCE) is the standard loss for two-class
    problems. Intuitively:

        If the true label is SEIZURE (y=1) and the model predicts
        p=0.95, the loss is small (the model is right).

        If the true label is SEIZURE (y=1) and the model predicts
        p=0.05, the loss is large (the model is very wrong).

    The formula:
        L = -[y * log(p) + (1-y) * log(1-p)]

    BCEWithLogitsLoss combines the sigmoid and BCE into one step
    for numerical stability -- it avoids computing log(sigmoid(x))
    separately, which can produce infinity or NaN for very large
    or very small logits.

A.4 Gradient, backpropagation, and gradient clipping

    GRADIENT: for each trainable parameter (e.g., a convolution
    filter weight), the gradient tells the optimiser "if I increase
    this weight slightly, how much does the loss change?" A positive
    gradient means increasing the weight increases the loss (bad),
    so the optimiser decreases it.

    BACKPROPAGATION: the algorithm that computes gradients for all
    parameters simultaneously by propagating the loss backward
    through the network, layer by layer, using the chain rule of
    calculus.

    GRADIENT CLIPPING: in deep networks, gradients can occasionally
    become very large ("exploding gradients"), causing the optimiser
    to take a catastrophically large step that destabilises training.
    Gradient clipping limits the total gradient magnitude to a
    maximum norm (1.0 in this study): if the combined gradient
    across all parameters exceeds 1.0, every gradient is scaled
    down proportionally so the total norm equals exactly 1.0.

A.5 Learning rate, weight decay, and AdamW

    LEARNING RATE (lr): controls how large a step the optimiser
    takes at each update. Too large and training becomes unstable
    (the model overshoots good solutions); too small and training
    is extremely slow or gets stuck.

    WEIGHT DECAY (wd)
    -----------------
    A regularisation technique that penalises large parameter
    values by shrinking every weight slightly at each optimiser
    step. A weight decay of 1e-4 means "at each step, multiply
    every weight by (1 - 1e-4)" before applying the gradient
    update; over thousands of steps this accumulates into a
    meaningful pressure that keeps weight magnitudes bounded.

    Why weight decay is needed:
      Neural networks have many more parameters than there are
      independent training samples (in this study: ~80K-1.2M
      parameters for ~220K training segments). Without any
      regularisation, the optimiser can drive individual weights
      to large absolute values that exactly fit the training set
      including its noise -- a model that memorises rather than
      generalises. Two failure modes follow:
        (i) Test-time predictions become brittle: a small input
            change causes large output swings because some
            weights are doing extreme work.
        (ii) Validation F1 plateaus or declines mid-training even
            as training loss continues to fall -- the classic
            signature of overfitting.
      Weight decay opposes both by imposing a continuous,
      direction-agnostic shrinkage that the optimiser must "earn
      back" through gradient signal from the data. Weights that
      contribute meaningfully to reducing loss survive the
      shrinkage; weights that fit only noise are pulled toward
      zero. Mathematically, weight decay is equivalent to placing
      a Gaussian prior on the parameters with mean zero and a
      fixed variance set by 1/wd.

    AdamW
    -----
    An optimiser that adapts the learning rate individually for
    each parameter based on the running history of its gradients
    (mean and variance). The "W" indicates decoupled weight decay
    (Loshchilov & Hutter, 2019), which applies the shrinkage
    directly to the parameters rather than mixing it into the
    gradient. The decoupling matters because Adam's adaptive
    step-size scales the gradient term but should not scale the
    regularisation term -- when the two are coupled (the original
    Adam-with-L2 formulation), the effective regularisation
    weakens whenever Adam's adaptive denominator is large,
    breaking the intended regularisation strength. AdamW
    preserves the configured weight decay magnitude regardless
    of gradient history and is now the default optimiser for
    most modern deep learning workloads.

    COSINE ANNEALING
    -----------------
    A learning-rate schedule in which the lr starts at its
    initial value and smoothly decreases along a half-cosine
    curve over the training budget, reaching a minimum of 1%
    of the initial value at the final epoch:

        lr(t) = eta_min + 0.5 * (lr_initial - eta_min) *
                (1 + cos(pi * t / T_max))

    where T_max is the epoch budget (20 for tuning, 100 for
    final training) and eta_min = 0.01 * lr_initial.

    Why a learning-rate schedule is needed:
      Training a neural network is most efficient with two
      qualitatively different phases. Early in training the
      weights are far from any good configuration and the
      gradient field is steep; large steps make rapid progress
      but small steps would crawl. Late in training the weights
      are near a local optimum and the gradient field is shallow;
      large steps now overshoot the optimum and oscillate
      around it, while small steps allow fine-grained settling.
      A constant learning rate is a compromise that is too large
      late in training (final loss plateaus higher than
      necessary) and not always large enough early on. A
      schedule -- decreasing over time -- handles both phases.

    Why cosine specifically (rather than step decay or
    exponential decay):
      Cosine annealing was introduced by Loshchilov & Hutter
      (2017) and has three properties that suit deep convolutional
      networks: (i) the decay is continuous, so there are no
      abrupt jumps that can momentarily destabilise training;
      (ii) the curve is gentle near the start (preserving high
      lr while exploration is still useful) and steepest near
      the end (allowing rapid convergence in the final phase);
      and (iii) the final lr is non-zero (1% of initial),
      preventing complete optimiser stagnation while still being
      small enough for fine-grained refinement. Step-decay
      schedules require manually choosing the milestone epochs
      and often produce visible loss-plateau steps; exponential
      schedules decay too fast in the middle phase. Cosine
      annealing has become the de facto standard for vision and
      time-series convolutional networks.

    Why this study uses cosine annealing with eta_min =
    0.01 x lr_initial:
      The 1% floor guarantees that even at epoch 100 the
      optimiser is still making non-trivial parameter updates.
      A lower floor (e.g. eta_min = 0) would freeze training in
      the final epochs, while a higher floor (e.g. 10%) would
      leave too much oscillation around the optimum. The 1%
      setting is the standard choice in the cosine annealing
      literature and matches the behaviour observed in our
      tuning logs, where validation F1 typically reaches its
      peak between epochs 8-15 of a 20-epoch budget and the
      gentle late-stage decay confirms rather than disturbs
      the trajectory.

    References:
      Loshchilov, I. & Hutter, F. (2017). SGDR: Stochastic
          Gradient Descent with Warm Restarts. ICLR 2017.
      Loshchilov, I. & Hutter, F. (2019). Decoupled Weight
          Decay Regularization. ICLR 2019.

A.6 Batch size and gradient noise

    Training data is processed in batches (groups of segments).
    The gradient computed from one batch is an approximation of the
    true gradient over the entire dataset.

    SMALL BATCHES (e.g., 16): noisier gradient estimates, but each
    step is cheaper and the noise can help the optimiser escape
    shallow local minima.

    LARGE BATCHES (e.g., 64): smoother gradient estimates, but each
    step is more expensive and the optimiser may converge to sharper
    (potentially less generalisable) minima.

    The batch size also affects GPU memory usage: larger batches
    require more VRAM. Powers of 2 (16, 32, 64) are preferred
    because GPU hardware is optimised for these sizes.

A.7 Dropout and regularisation

    REGULARISATION: any technique that prevents a model from
    memorising the training data (overfitting) and encourages it
    to learn general patterns that transfer to unseen data.

    DROPOUT: during training, a random subset of neurons (or entire
    channels) is temporarily set to zero at each forward pass. This
    forces the network to learn redundant representations that do
    not rely on any single neuron, improving generalisation.

    SPATIAL DROPOUT (Dropout1d): instead of dropping individual
    values, entire convolutional feature-map channels are dropped
    across the full time dimension. Because adjacent time steps
    within a single feature map share overlapping receptive fields
    (and are therefore highly correlated), element-wise dropout on
    a single cell is easily recovered from its temporal neighbours;
    spatial dropout avoids this by removing the entire feature map,
    forcing the remaining feature maps to carry the signal.

    Terminology note: "channel" here means a learned convolutional
    feature map, not an EEG recording electrode. The recordings in
    this study are single-electrode, so the input tensor has shape
    (batch, 1, time) and the num_filters feature-map dimension is
    introduced only after the first convolution. Dropping a feature
    map does not drop a physical electrode.

    The dropout rate (e.g., 0.30) specifies the probability that
    each feature map is dropped: at 0.30, roughly 30% of the
    num_filters feature maps are zeroed out in each training batch.
    Dropout is disabled during evaluation (model.eval()), so all
    feature maps contribute to the final prediction.

A.8 Early stopping and patience

    EARLY STOPPING: a technique to prevent overfitting by monitoring
    a validation metric (macro F1-score in this study) after each
    training epoch. Training is halted when the metric stops
    improving.

    PATIENCE: the number of consecutive epochs without improvement
    before training is stopped. A patience of 5 means: "if the
    validation F1 has not exceeded its best value for 5 epochs in
    a row, stop training and keep the best model."

    This prevents the model from training past its peak performance
    into the overfitting regime, where training loss continues to
    decrease but validation performance degrades.

    MINIMUM-EPOCH GATE: an additional rule used in this study's final
    training stage that prevents early stopping from firing before a
    fixed epoch count is reached. The gate is set to epoch 40 because
    the cosine learning-rate schedule (Section 7.6.6) is nearly flat
    in its first ~30 epochs -- the model is still in a high-LR
    exploration phase where validation F1 is volatile and not yet
    converged. Allowing early stopping during this phase would
    capture under-trained models. The gate forces every model to
    traverse the high-LR phase unconditionally; the patience-15 stop
    only applies from epoch 40 onward, when the LR has decayed to
    ~36% of its initial value and the model is genuinely converging.
    All four ablation models (M1-M4) use the same gate value so that
    any observed performance difference reflects architectural
    variables, not differential exposure to the LR schedule's
    fine-tuning phase.

A.9 Mixed precision (AMP)

    Automatic Mixed Precision (AMP) uses 16-bit floating-point
    numbers (FP16) instead of 32-bit (FP32) for the forward and
    backward passes through the network. This approximately halves
    memory usage and can double throughput on GPUs with dedicated
    FP16 hardware (Tensor Cores on V100, A100, L40S).

    The GradScaler dynamically adjusts a scaling factor to prevent
    the smaller FP16 number range from causing gradient underflow
    (gradients too small to represent, rounded to zero). Weight
    updates are always performed in FP32 to maintain precision
    where it matters most.

A.10 Receptive field

    The receptive field of a convolutional network is the span of
    input samples that can influence a single output value. In a
    TCN with dilated convolutions, the receptive field grows
    exponentially with depth:

        Layer 1 (dilation 1):  each output sees 7 input samples (k=7)
        Layer 2 (dilation 2):  each output sees 19 input samples
        Layer 3 (dilation 4):  each output sees 43 input samples
        ...
        Layer 6 (dilation 32): each output sees 757 input samples

    A receptive field of 757 samples at 500 Hz means the network
    can "see" 1.514 seconds of EEG history when making a prediction
    at any given time step. If the receptive field is too small
    (e.g., 125 samples = 0.25 s), the network cannot capture
    seizure patterns that evolve over longer timescales.

13. INTERPRETABILITY ANALYSIS -- PER-PREDICTION BRANCH ATTRIBUTION
--------------------------------------------------------------------------------

13.1 Motivation

    The multi-scale architecture used in M3 and M4 (Section 6) contains
    three parallel temporal-convolutional branches with distinct
    dilation schedules: branch 1 [1, 2, 4] (fine), branch 2
    [8, 16, 32] (medium), and branch 3 [32, 64, 128] (coarse). The
    aggregate branch-ablation routine (interpretability_analysis.py,
    run_branch_ablation) reports a single macro-F1 contribution per
    branch over the entire partition. That measurement answers "which
    branch matters most on average across the dataset" but cannot
    answer "which temporal scale drove THIS prediction." The per-
    prediction question is required to (i) differentiate the temporal
    scale that triggered a true-positive seizure call from the scale
    that misled a false-positive, and (ii) justify the multi-scale
    design by demonstrating that different seizure morphologies
    recruit different branches rather than depending uniformly on the
    single most informative scale.

13.2 Method -- exact Shapley value attribution over three branches

    For each segment, the contribution of each branch to the model's
    pre-sigmoid logit was attributed using the Shapley value (Shapley,
    1953). A coalition v(S) was defined as the logit produced when only
    the branches in subset S are active, with the remaining branches'
    outputs zeroed before fusion. With K = 3 branches the power set
    contains 2^K = 8 coalitions, so the Shapley value of each branch is
    computed exactly per sample without any sampling approximation:

        phi_k = sum over S subset of N\{k} of
                [ |S|! (K - |S| - 1)! / K! ] * ( v(S U {k}) - v(S) )

    By the efficiency axiom, phi_B1 + phi_B2 + phi_B3 equals
    v({1,2,3}) - v(empty) for every sample. This identity is logged at
    run time as a numerical sanity check; the maximum and mean absolute
    residuals are recorded in the per-model JSON summary.

13.3 Justification of Shapley over alternative attribution methods

    Three branch-level attribution methods were considered: leave-one-
    out (LOO) ablation, Shapley value attribution, and gradient-based
    methods (Integrated Gradients, DeepLIFT). Shapley was selected for
    the following reasons.

    The M3 and M4 branches do not span disjoint frequency bands.
    Branch 2 uses dilations [8, 16, 32] and branch 3 uses dilations
    [32, 64, 128]. The shared dilation = 32 means the two branches
    sense overlapping temporal scales, and the learned fusion layer
    may carry redundant information across the pair. LOO measures only
    the marginal effect of removing one branch with the other two
    intact, which systematically under-attributes redundant branches:
    zeroing one of a redundant pair produces only a small drop because
    the other branch compensates. Shapley averages the marginal
    contribution across all 2^K coalitions and therefore credits each
    branch fairly when redundancy is present.

    Integrated Gradients and DeepLIFT were designed for attribution to
    input features. Applying them at the branch-output level requires
    (i) selecting a reference activation (zero, mean ictal, mean non-
    ictal -- each choice changes the attribution), and (ii) aggregating
    element-wise gradients across the (num_filters, T) branch-output
    tensor into a single per-branch number (sum, L1 norm, mean --
    another arbitrary choice). Both are free parameters that weaken
    the methodological defence.

    Shapley over K = 3 branches is exactly computable in eight forward
    passes per batch, has no free hyperparameters beyond the value
    function (the model's logit), and satisfies the efficiency, dummy,
    symmetry, and additivity axioms.

    Reference:
        Shapley, L. S. (1953). A Value for n-Person Games. In Kuhn,
            H. W. & Tucker, A. W. (eds), Contributions to the Theory
            of Games, Volume II, pp. 307-317. Princeton University
            Press.

13.4 Implementation

    The Shapley computation is implemented in
    branch_shapley_analysis.py. Two helpers were added to
    interpretability_analysis.py:

        compute_branch_outputs(model, x)
            Runs the three branch TCN stacks once and returns
            (o1, o2, o3) for re-use across multiple fusion masks.

        forward_with_branch_mask(model, x, zeroed_branches,
                                 branch_outputs=None)
            Performs the M3 or M4 forward pass with the listed branches
            zeroed before fusion. Accepts pre-computed branch outputs
            so the branch convolutions are not repeated across the
            eight coalitions.

    The existing run_branch_ablation function was refactored to call
    forward_with_branch_mask internally; its JSON output and aggregate
    F1 semantics are preserved unchanged. branch_shapley_analysis.py
    reuses the model-loading helper (load_model_weights) and reads the
    canonical enriched splits manifest used by all training and
    evaluation scripts:

        /scratch/22206468/INPUT_DATA/data_splits_outputs/
            data_splits_nonictal_sampled_filtered_enriched.json

    Using this manifest -- rather than the raw data_splits.json
    consumed by interpretability_analysis.py for the aggregate
    ablation -- guarantees that the per-prediction attribution is
    computed on exactly the same val / test segments as the headline
    MultiScaleTCN_evaluation.py / MultiScaleTCNAttention_evaluation.py
    results, and inherits the per-record fields mouse_id, chrono_idx,
    and t_start_sec added by enrich_manifest.py.

    Branch outputs are computed once per batch and reused across the
    eight coalitions, so the wall-time cost is approximately 1.3 times
    a standard test-set inference pass per model rather than eight
    times. All forward passes run on GPU under torch.no_grad().

13.6 Decision threshold

    The TP / FP / TN / FN categorisation uses threshold = 0.5 on
    sigmoid(logit_full) to match the convention of the aggregate
    branch-ablation reported by run_branch_ablation. The raw logit and
    sigmoid probability are written to the CSV so the categorisation
    can be recomputed at any other operating threshold without
    re-running the inference pass.

13.7 Caveat -- out-of-distribution coalition baseline

    The empty coalition v(empty) is produced by zeroing all three
    branch outputs before fusion. The fusion layer was trained on the
    joint distribution of three non-zero branch outputs, so v(empty)
    is an out-of-distribution input. Shapley values that quantify the
    relative dominance of one branch over another within the same
    sample (phi_Bi - phi_Bj) are unaffected, because v(empty) enters
    all three phi_k with the same weight and cancels in the
    difference. Absolute phi_k values, by contrast, depend on the
    baseline and should be interpreted as the trained model's reliance
    on each branch rather than as the architecture's necessity of each
    branch. A retrained ablation (training three separate models, each
    with one branch removed) would be required to make the latter
    claim, and is outside the scope of this analysis.

13.8 Partition policy

    Per-prediction Shapley attribution is reported on the held-out
    test partition (Section 2). Running on the validation partition is
    supported but carries the same threshold-selection bias as any
    other validation-set evaluation (Section 7); validation-partition
    Shapley results are intended for pipeline verification, not for
    publication. The script logs a warning when invoked with
    --partition val.
